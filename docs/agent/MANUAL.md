# AGENTS v2.1 独立再レビュー

更新日: 2026-10-07

## 結論
現在のv2.1はそのままでも運用可能な水準にある。
v2で問題だった過剰停止、Child統合の曖昧さ、無関係なGit状態による停止、AGENTS改善メタルールの常駐は既に改善されている。
大きな構造変更は不要で、2点だけ補強する。

## 維持する点
- 1責任単位で作業し、必要な場合だけChildへ分割する。
- 分解は上位→下位、統合・検証は検証済み下位→上位とする。
- Childの検証済みcommit SHAを確認し、Parentが採用SHAと統合状態を所有する。
- 既存コード・テスト・契約から安全に解ける小判断は質問せず自律実行する。
- 新仕様、UX、公開API、データモデル、構成、責任範囲など結果を実質的に変える判断だけを確認する。
- 無関係なdirty/untrackedは保護したまま作業を続ける。
- Git・作業MDをAI/環境間の共通状態として使い、特定AIやIDEを前提にしない。

## 修正する点
### Child handoff
結果・境界・依存・前提・検証結果に加え、残る制約と未検証条件を渡す。
テスト済みcommitでも検証範囲外の条件はあり得るため、Parentが安全性を過大評価しないために必要と判断した。

### 検証
変更に最も近い検証から開始し、成功後に影響範囲へ広げる。
常時フルテストを要求せず、失敗時は変更との因果を確認して責任範囲内の回帰だけを修正・再検証する。

## 削除・追加しない点
現行v2.1からさらに削除すべき恒久ルールは見つからなかった。
一方、Parent統合commitの別管理、固定ファイル数、固定コンテキスト量、常時フルテスト、特定AI向け手順、将来の大規模化を想定した追加状態管理は現時点では不要と判断した。

## commit SHAについて
Childのcommit SHAは「どの検証済み成果を採用したか」を固定する識別子として十分である。
安全性そのものはSHAでは保証できないため、共有境界・前提・検証結果・残る制約と、Parent統合後の接続点/回帰検証を組み合わせる。
追加の独自IDや状態ファイルは作らない。

## 適用判断
現在のv2.1はこの2点を反映しなくても使用可能。
ただし反映コストが小さく、実際のhandoff欠落と過剰検証を直接抑えるため、v2.1最終版には採用を推奨する。
