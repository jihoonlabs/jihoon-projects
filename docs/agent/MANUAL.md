# AGENTS v2 独立レビュー候補

作成日: 2026-10-07

## 結論
現在のEpic/Child分業は維持する価値が高い。ただし品質を上げる中心は「規則を増やすこと」ではなく、各Childの責任を狭くし、必要な文脈だけを読み、統合境界を明示して検証することに置く。

AGENTSは常時読む最小の操作規約に絞り、改善履歴・調査方法・詳細仕様を抱え込ませない。

## 主な変更
- AGENTSの「AGENTS改善」章を削除し、改善運用をWORKへ移した。
- 停止条件を安全上の問題に限定し、調査で解決できる不確実性ではAIが止まらないようにした。
- 親MDをRouter兼統合契約、Child MDを現在作業の所有者として明確化した。
- Child統合時に、diffだけでなく接続点・共有契約・親回帰を確認するルールを残した。
- 検証は変更に近いものから段階的に広げ、未実行を明示する方式にした。
- gate/harnessは全面導入を義務化せず、既存CI/script/hookを優先し、繰り返す実害だけ機械化する方針にした。

## 判断理由
最近のcoding-agent運用では、巨大な常設指示より短いAGENTSを地図として使い、必要な文書をオンデマンドで読む方向が強い。長時間作業では明確な進捗・検証可能な状態・次セッションへ渡せる成果物が重要で、hook等による機械的検証も有効である。

一方、このリポジトリではEpic/Childによる責任分割自体がcontext isolationとblast radius縮小に役立つ。これを捨てて中央の巨大なコンテキストへ集約する理由はない。弱点はChild数ではなく、親への履歴重複とChild間の統合契約が曖昧になる場合にある。

## 適用
この候補は比較用reviewブランチだけに置く。mainおよび元の `docs/agents-v2` は変更しない。
最終採用は他候補との比較後に決定する。
