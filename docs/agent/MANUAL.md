# AGENTS v2.1 独立再レビュー

更新候補作成日: 2026-10-07

## 結論
現在のv2.1はそのままでも実用可能で、v3相当の再設計は不要。
正式v2.1前に、handoffと検証の2点だけ小さく補強し、context/変更境界の重複表現を少し削る案を推奨する。

## 維持する点
- 1責任単位と必要時だけChildへ分割する方針。
- 上位→下位で分解し、検証済み下位→上位で逆順統合する方針。
- 既存コード・テスト・契約から安全に解ける小判断は自律処理し、新仕様・UX・公開契約・責任範囲変更だけ確認する境界。
- Childのcommit SHAをhandoffし、Parentが実際の採用SHAと統合状態を所有する方式。
- 無関係なdirty/untrackedを保護しつつ、それ自体では作業停止しないGit方針。
- 特定モデル・IDE・固定context量・常時full testを前提にしないこと。

## 修正する点

### 1. handoffに未解消条件を含める
検証済みSHAだけでは「何を実行していないか」「どの環境条件が残るか」がParentに伝わらない。
そのためChildは検証結果に加え、統合判断へ影響する残る制約・未検証条件だけを残す。
固定テンプレート化はせず、必要な場合だけ記録する。

### 2. 検証を段階的に広げる
変更に最も近いテスト・チェックから始め、blast radiusに応じて関連チェックと統合回帰へ広げる。
これにより毎回full suiteを強制せず、Child単体テストだけで統合を完了することも防ぐ。

### 3. 変更境界を責任基準へ寄せる
「範囲外ファイル」という形式的な境界より、承認済み責任・仕様を越えるかで判断する。
責任完了に直接必要な小さな接続・回帰修正は自律対応できる一方、新仕様や公開契約変更は引き続き確認対象とする。

## 削除・縮約する点
- 開始contextとcontext節で重複していた「必要な対象コード」を、必要時の追加探索という1つの規則へ統合。
- 作業MDの保持項目を、再開・統合に必要な情報中心へ縮約。
- 検証節の重複した「未実行・報告」表現を整理。

## そのまま使えるか
使える。ただし正式v2.1として固定する前なら、今回の小修正を入れる方を推奨する。
理由は新しい運用思想を足すためではなく、既に採用したChild/Parent方式で実際の統合判断に必要な情報を欠かさず、検証コストを過不足なくするため。

## 過剰先回りを避けた点
- SHA以外の複雑な状態機械を導入しない。
- handoff schemaを固定しない。
- 並列AI coordination protocolを新設しない。
- 特定AIの推論能力やtool supportを要求しない。
