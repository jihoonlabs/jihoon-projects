## 3文書の役割
- AGENTS.md: 常時必要な境界と判断だけ。機能履歴、研究結果、固定テスト一覧を置かない。
- WORK.md: 今回の改善作業の状態。汎用テンプレートや通常作業の必読資料にしない。
- MANUAL.md: 独立比較の根拠と未検証事項。機能ごとの報告書を強制しない。

追加ファイル、skill、CI、ブランチ階層の変更は行わない。現在の環境と契約に合わせて検証を選び、Laravel/React/MicroPython全部の検査を毎回要求しない。

## 状況別レビュー
以下は規約を読む手動レビューであり、agent実行試験ではない。

| 状況 | 期待する判断 | 結果 |
|---|---|---|
| 確定仕様内で実装方法が2案ある | 小さい既存方式を選んで続行 | 自律条項で許容 |
| 承認済み修正で同じ検査が失敗 | 原因を修正し影響検査を再実行、再承認不要 | 継続・検証条項で許容 |
| 関係ないファイルがdirty | 保護して対象作業を続行 | Git条項で許容 |
| 対象に他者の未完了変更がある | 所有範囲が不明なら上書きせず確認 | Git条項で停止 |
| MDの進捗がコードより古い | 事実確認して担当MDを更新 | 不一致条項で許容 |
| API提供側とUI側の契約が違う | 必要な関連資料を調べ、確定契約内なら修正 | 調査・統合条項で許容 |

| AGENTSが機能mergeで競合 | 統合先を維持、差分報告。規約変更は別承認 | 統合・規約条項で保護 |

## 検証と限界
原本との差分が上記3文書だけであること、参照先・改行・見出し・規約の相互矛盾を確認する。検証HEADを記録することで、子の以前の成功を統合後の成功と混同しない。アプリコードは変更せず、アプリテスト・実ブラウザ試験は再実行しない。

実際のagentでの停止回数、コンテキスト使用量、統合不具合削減は未測定。採用後の最初のChildとEpic統合で、不要な停止・無関係な読込み・契約漏れが減るか確認し、問題がなければ規則を追加しない。
