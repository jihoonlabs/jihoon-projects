# AGENTS v2.1 更新報告

更新日: 2026-10-07

## 結論
v2の基本構造を維持し、実作業と複数の独立reviewで根拠が強かった改善だけを統合した。
大きな設計変更ではないためv3ではなくv2.1とする。

## MANUAL記録方針
各作業のMANUALはユーザー向けの完了報告とし、後からコードやWORKを読み直さなくても「なぜ行ったか・何を変えたか・どう実装したか・どの観点で検証したか」を短く把握できるようにする。
背景・目的は1〜2行で十分とし、長い経緯やコードから容易に分かる情報は重複させない。

## 主な変更

### 1. AIを止めすぎない
既存コード・テスト・契約から安全に解消できる小さな判断はAIが自律的に進める。
ユーザー確認は新仕様・UX・公開API・データモデル・構成・責任範囲など、結果を実質的に変える判断に絞った。

### 2. ChildからParentへの統合を明確化
Childは結果・境界・依存関係・前提・検証結果に加え、残る制約・未検証事項とcommit SHAをhandoffする。
Parentは実際に採用したSHAと最終統合状態を所有する。

分解は上位から下位へ行い、組み立ては検証済みの下位作業から上位へ戻す。
統合後はmerge成功だけでなく、API・データ・権限・状態・UI等の実際の接続点と親範囲の回帰を確認する。

### 3. 検証を必要範囲から広げる
変更に最も近い有効な検証から開始し、影響範囲に応じて関連テスト・型・Lint・build・syntax等へ広げる。
常時フルテストを機械的に要求しない。

### 4. Git状態の扱いを現実的に修正
関係のないdirty/untrackedは保護するが、それだけで作業全体を停止しない。
現在作業と衝突する変更、競合、ブランチ不一致は勝手に解消せず報告する。

### 5. AGENTS改善を強制しない
各作業AIはAGENTS改善点を探す必要はない。
実作業中に明確な改善点が見えた場合だけ報告し、なければ何も追加しない。
報告された候補と定期的な公式情報・公開事例の確認をAGENTS専用作業で統合し、変更根拠がある時だけ更新する。

## 運用モデル
特定のClaude、Codex、IDEを前提にしない。
作業を必要な責任単位に分け、各環境は能力に合う作業を担当する。
Gitと作業MDを共通状態・引継ぎインターフェースとし、下位で検証した結果を上位へ順に統合する。

この考え方自体をAGENTSに長く説明せず、実行に必要な最小ルールだけをAGENTS.mdへ残す。

## Version policy
小さな改善・統合・削除・調整はv2.xとして扱う。
大きな作業構造や運用モデル自体を変更する場合だけmajor versionを上げる。
