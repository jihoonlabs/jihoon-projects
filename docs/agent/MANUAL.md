# AGENTS v2.1 再レビュー報告

更新候補作成日: 2026-10-07

## 結論
現在のv2.1はそのままでも実用可能で、構造を変える必要はない。
再レビューでは新しい仕組みを追加せず、handoffと検証の2点だけを小さく補強し、停止条件の重複を1点削った。

## 維持する点
- 1責任単位を基本にし、必要な時だけChildへ分割する。
- 分解は上位→下位、統合・検証は検証済み下位→上位の逆順で行う。
- Childの採用commit SHAと統合状態をParentが所有する。
- 無関係なdirty/untrackedを保護しつつ、それだけでは全作業を停止しない。
- 既存コード・テスト・契約から安全に解消できる小判断はAIが自律的に進める。
- Git・作業MDをAI/環境間の共通状態として使い、特定AI・IDE固有機能を前提にしない。

## 修正する点

### Child handoff
Childの検証結果だけでは、未実行条件や残制約を別環境が「問題なし」と誤読する可能性がある。
そのため、handoffには結果・境界・依存関係・前提・検証結果に加え、残る制約・未検証条件を含める。

### 検証
毎回同じ広さでテストするのではなく、変更に最も近いテストから開始し、影響範囲に応じて関連回帰・型・Lint・build等へ広げる。
ただしParent統合時はChild間の接続点と親範囲の回帰確認を維持する。

## 削除・縮約する点
統合節の「新仕様・設計判断が必要なら確認」は、第1節の確認境界と重複し「設計判断」の解釈でAIを止めやすい。
「第1節の確認条件に当たる場合だけ確認」へ集約する。

## commit SHAについて
現在の方式で十分と判断する。
Parentが採用したChild commit SHAと統合状態を持てば、AIや端末が変わっても同じ成果物を特定できる。
Parent自身のcommit SHAを作業のたびにMDへ複製する規則は、Gitから取得できる履歴の重複になるため追加しない。

## 採用しない追加案
- 強制的なParent SHA記録
- 常時フルテスト
- 固定コンテキスト量・固定ファイル数
- 特定AI製品の機能に依存するhandoff
- 実際に発生していないGit事故を想定した禁止事項の追加

## 適用判断
現在のv2.1は大きな欠陥がなく、そのままでも使用可能。
今回の差分はv3相当の構造変更ではなく、v2.1の小さな完成度向上として扱うのが妥当。
