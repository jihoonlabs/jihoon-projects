# AGENTS v2.1 更新報告

更新候補作成日: 2026-10-07

## 結論
v2の基本構造は維持し、独立reviewで根拠が強かった改善だけを統合した。
大きな設計変更ではないためv3ではなくv2.1とする。

## 主な変更

### 1. AIを止めすぎない
v2では「複数の妥当案」「不確実性」「文書と実装の矛盾」「想定外Git状態」が広く停止条件になっていた。
v2.1では、既存コード・テスト・契約から安全に解消できる小さな判断はAIが自律的に進める。
ユーザー確認は新仕様・UX・公開API・データモデル・構成・責任範囲の変更など、結果を実質的に変える判断に絞る。

### 2. ChildからParentへの統合を明確化
分業そのものではなく統合品質を強化した。
Childは結果・境界・依存関係・前提・検証結果を残し、検証済みcommit SHAをhandoffする。
Parentは実際に採用したSHAと最終統合状態を所有する。

分解は上位から下位へ行い、組み立てはその逆に、検証済みの下位作業から上位へ戻す。
統合後はmerge成功だけでなく、API・データ・権限・状態・UI等の実際の接続点と親範囲の回帰を確認する。

### 3. Git状態の扱いを現実的に修正
関係のないdirty/untrackedは保護するが、それだけで作業全体を停止しない。
現在作業と衝突する変更、競合、ブランチ不一致だけを停止・報告対象とする。

### 4. AGENTS自身の改善ルールを外す
通常の全AI作業で毎回AGENTS改善を検討させる必要はないと判断した。
改善は実作業で摩擦が見つかった時に別reviewとして行う。
これにより常時コンテキストとメタ作業を減らす。

## 運用モデル
特定のClaude、Codex、IDEを前提にしない。
作業を必要な責任単位に分け、各環境は能力に合う作業を担当する。
Gitと作業MDを共通状態・引継ぎインターフェースとし、下位で検証した結果を上位へ順に統合する。

この考え方自体をAGENTSに長く説明せず、実行に必要な最小ルールだけをAGENTS.mdへ残した。

## 採用しなかった案
- すべての作業を強制的にChildへ分割する
- 固定のファイル数・コンテキスト量を上限化する
- 毎回フルテストやブラウザ検証を必須化する
- 特定AI製品・IDEの機能を前提にする
- 大規模化で起きるかもしれない問題を先回りして規則化する

## 適用方針
現在進行中のTicket作業には遡及適用しない。
ユーザー確認後、次に新しく開始する作業からv2.1を適用候補とする。
