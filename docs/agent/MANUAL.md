# AGENTS 独立レビュー候補

作成日: 2026-10-07  
基準: `docs/agents-v2`  
候補branch: `review/agents-v2-codex-20261007b`

## 判断

現在のv2は、最小context、自律実行、Child統合検証という方向は妥当である。一方、実行規則、AGENTS自体の改善手順、ユーザー向け報告が混在し、すべての作業が不要なメタ規則まで読む構成になっている。

実際のTicket作業では、Child文書が詳細な検証結果を保持している一方、Epic Routerのbranch名・状態と一致しない例があった。また、単純な統合にも専用integration branchと文書が追加され、管理段階が増えている。

最近のCodex指針は、大きな `AGENTS.md` ではなく短い地図と必要時の段階的探索を推奨する。最新モデルに毎回すべての文書を読ませたり同じ全検証を要求したりすると、contextと時間を浪費しやすい。反対に分業作業は、個別Childの成功だけでは信頼できないため、契約・共有境界・統合後の動作を証拠として残す必要がある。

## 主な変更

- `AGENTS.md` からAGENTS改善キャンペーンとrollout説明を外し、全作業に共通する境界だけを残した。
- 固定された必読ファイル一式ではなく、小さな開始contextと必要性に基づく自律探索を定めた。
- 質問条件を製品判断、重大な曖昧さ、危険な操作へ絞り、明らかな実装・テスト・回帰修正は完了まで自律実行させる。
- Child分割は、独立価値・境界・検証・隔離の利点がある場合だけとし、小さな作業にbranchやMDを強制しない。
- Child handoffにbase/head、契約、schema・migration・権限・共有状態、検証証拠、残存リスクを含める。
- 統合は最新の親へChildを1つずつ適用し、mergeの成否ではなく接続点と親の回帰で判定する。
- integration branchを常設工程ではなく、競合・複数Child・高リスク境界のための手段に限定した。
- 検証をrisk-basedに変更した。近いテストから広げ、文書変更には全アプリテストを要求せず、統合では親の検証を省略しない。
- 同じ事実をRouter、Child、MANUALへ重複させないよう、文書の所有権を明確にした。

## 維持したもの

- branchとGit状態の確認
- 他者の変更の保護
- コード・テスト・Gitを実装事実の基準とする方針
- 検証前の完了報告禁止
- ユーザー承認のないmain変更・破壊的Git操作の禁止
- 日本語中心の開発文書規則

## 削除・縮小したもの

- すべての作業でAGENTS改善候補を確認するメタ規則
- 小さな不確実性でも質問を誘発する広すぎる停止条件
- 変更種類に関係なく一律に要求する全検証
- 単純なfast-forwardにもintegration branch・文書を作る暗黙の手順
- 親とChildへ同じ実装・検証状態を重複記録する運用

## WORKへ移したもの

- 分割判断基準
- Router/Childの最小schema
- Child handoffと段階的統合手順
- 変更種類別の検証選択
- AGENTS規則の維持管理基準

## 適用判断

この候補はv2より `AGENTS.md` を短く安定させつつ、実際の弱点である分業後の統合には、より具体的な証拠と検証を要求する。実装方法には広い自律性を与え、製品判断・外部影響・Gitリスクには狭く明確な承認境界を設けた。その結果、小さな作業は速くなり、複数Childが接続する作業は安全になる。

進行中branchには遡及適用せず、最終候補の採用後に開始する新しい作業から適用するのが適切である。
