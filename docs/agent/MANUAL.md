# AGENTS v2.1 独立再レビュー

更新日: 2026-10-07

## 結論
現在のv2.1は、以前のv2で問題だった過剰停止、Child統合の曖昧さ、無関係なGit状態による停止、AGENTS改善メタルールの常駐を既に改善している。
そのため大きな再設計は不要と判断し、実質的な変更は2点に限定した。

## 変更点

### 1. Child handoffに残る制約を追加
Childは結果・共有境界/契約・依存/前提・検証結果に加え、統合後も残る制約を渡す。
成功したChildでも未対応条件や検証限界があり得るため、ParentがSHAだけで安全性を過大評価しないための情報とする。

### 2. 検証を近いものから広げる
変更に最も近いテストから開始し、成功後に影響範囲に応じて型・Lint・build・回帰へ広げる。
常時フルテストは要求せず、失敗時は変更との因果を確認して責任範囲内だけを修正する。

## 維持したv2.1判断
- 既存コード・テスト・契約から解ける小判断は質問せず自律実行する。
- 新仕様、UX、公開API、データモデル、構成、責任範囲など結果を変える判断だけを確認する。
- 分解は上位→下位、統合は検証済み下位→上位とする。
- Childの検証済みcommit SHAを確認し、Parentが採用SHAと統合状態を所有する。
- 無関係なdirty/untrackedは保護したまま作業を継続する。
- AGENTS改善サイクルを通常作業の常時ルールにしない。
- 特定AI、IDE、固定ファイル数、固定コンテキスト量を前提にしない。

## 判断理由
現在のリポジトリではv2.1で主要な運用上の摩擦は既に処理されている。追加ルールを増やすより、ChildからParentへ渡す情報の欠落と検証コストだけを補正する方が目的に合う。

最近のcoding-agent運用も、巨大な常時指示ではなく短い入口から必要な情報を段階的に探索する方式、実装方法を細かく縛るより検証可能な境界を置く方式を支持している。

## 適用
このブランチはv2.1との独立比較用候補。mainおよび `docs/agents-v2` は変更しない。
