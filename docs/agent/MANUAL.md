# AGENTS v2 独立レビュー候補

更新日: 2026-10-07

## 結論
v2の方向性は維持しつつ、常時読む規則をさらに減らした。AGENTSは作業原則・統合・コンテキスト・検証・Git安全性に限定し、改善サイクル自体の詳細はWORKへ移した。

## 現在方式で確認した問題
- `feature/personal-game-ai` のEpic MDはChild統合のたびに実装・検証履歴が増え、Routerとしては過大になっている。
- Child分割は明確だが、親が統合時に必要とする契約が一定でないため、Child単体成功と全体成功の間に抜けが生じやすい。
- v2の確認条件は安全だが、軽微な実装判断まで「不確実性」と解釈すると不要な停止を誘発する。
- WORK/MANUAL/AGENTS間に改善方針の重複があり、常時コンテキストとしての価値が低い文章が残っていた。

## 核心変更
- Childに最小のintegration handoffを要求し、親は全Child履歴ではなくhandoff + diff +接続点を検証する。
- 「質問する条件」を公開契約・UX・データ・安全性・範囲変更など影響のある判断に限定し、既存仕様内の実装は自律継続する。
- 作業MDを現在状態中心にし、完了ログの累積を抑える。
- 検証を変更近傍→影響範囲の順に広げ、無関係な全体テストの常時実行を要求しない。
- 想定外Git状態でも無関係な既存変更なら保全して継続し、自分の変更と安全に分離できない場合だけ停止する。
- AGENTS改善サイクルの運用説明をAGENTS本体から削り、WORKへ集約した。

## 判断理由
最近のcoding agentは詳細な手順を大量に与えるより、短い恒久的guardrailと必要時の自律探索を組み合わせる方が適している。公開AGENTSの有用な共通点も、具体的な検証方法、最小変更、必要な範囲だけ読むことにあり、一般論の大量追加ではない。

このリポジトリでは特にEpic/Child分業そのものより、統合時の情報受け渡しと親側の接続検証が品質を左右する。そのため新しい管理層を増やさず、既存MDにhandoffだけを残す方式を採用した。

## 適用
このブランチは独立比較用候補。mainおよび `docs/agents-v2` は変更しない。
