# AGENTS v2 独立レビュー

作成日: 2026-10-07

## 結論
v2の「最小コンテキスト」「Child統合強化」「既存変更保護」は維持する。一方、AGENTS改善そのものの手順や重複した文書説明は常時読み込む規則から外し、実行時の判断基準を短くした。

## 主な問題
- Child分割は有効だが、個別成功に集中すると共有API・状態・権限・UIなどの接続点で回帰が残る。
- 「必要なものだけ読む」が強すぎると、自律探索まで抑制して不足文脈と追加質問を生む。
- 「不確実なら停止」が広すぎると、コード・テスト・既存仕様から解決できる判断でも作業が止まる。
- AGENTS/WORK/MANUALに運用方針を重複させると、毎回のcontextと文書同期コストが増える。
- 全検証を一律に要求すると小変更でもコストが高く、逆に本当に重要な統合接続点の確認が埋もれやすい。

## この候補の変更
- 自律探索を「小さく開始し、必要な証拠に応じて広げる」方式へ変更。
- ユーザー確認を、成果に実質的な影響を与える決定・不可逆操作・範囲変更へ限定。
- Child作成条件を「小さいこと」ではなく、独立責任・並行性・blast radius分離の価値で判断。
- Childの共有境界と依存関係を明示し、統合後は変更された接続点を優先検証。
- 検証を変更箇所に近いテストから始め、リスクに応じてsuite/build/browserへ拡張。
- AGENTS改善サイクルをAGENTS本体からWORKへ移し、通常作業の常時contextから除外。
- MANUALはユーザー向け成果報告だけに限定。

## 判断根拠
公式Codex運用はAGENTS.mdを永続的なrepository contextとして使いつつ、タスク自体はIssueのように具体的な対象と情報を与えることを推奨している。AGENTS.md公開仕様もproject固有のcommands・tests・conventionsなど実行に必要な情報を中心にしている。GitHubのagent instructionsは階層化・path-specific instructionsを支援しており、すべての詳細をrootへ集約する必要はない。

このrepositoryでは既にEpic/Child分割が十分機能しているため、さらに役割や階層を増やすより、Child間の契約と統合検証を補強し、停止条件と常時contextを減らす方が効果が高いと判断した。
