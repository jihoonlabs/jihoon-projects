# AGENTS v2.1 独立再レビュー

更新日: 2026-10-07

## 結論
現在のv2.1はそのまま運用可能な水準にある。
大きな構造変更は不要で、v3へ上げる理由もない。
今回の候補では、既存ルールへ2点だけ統合した。

## 維持する点
- 小さく可逆な実装判断をAIが自律処理し、新仕様・公開契約・責任範囲等の実質的な判断だけ確認する。
- 必要な時だけ責任単位へ分割し、上位→下位に分解、検証済み下位→上位に統合する。
- Parentが採用したChild commit SHAと統合状態を所有する。
- merge成功を完了とせず、共有境界・接続点・親範囲の回帰を確認する。
- 無関係なdirty/untrackedを保護しつつ、それだけで全作業を停止しない。
- Git・コード・テストを実装事実の正とし、MDへ履歴を重複蓄積しない。

## 修正する点
1. Child handoffに、残る制約と未検証条件を含める。
   成功結果だけでは、別AIや別環境へ渡した時に統合側が安全性を過大評価する可能性がある。
2. 検証は変更に最も近いものから始め、成功後に影響範囲へ広げる。
   常時full suiteを要求せず、変更規模に応じた検証強度を保つ。

## 追加しない点
- 新しい管理階層やhandoff形式
- 固定のcontext量・ファイル数
- 特定AI・IDE・agent機能への依存
- 常時full testやbrowser test
- 実際に観測していない将来リスク向けの予防規則

## 判断
commit SHAは採用物の識別には十分だが、統合成功そのものの証明ではない。
現在のv2.1はSHAとは別に統合状態と接続・回帰検証を要求しているため、この分離を維持すれば十分である。

今回の変更は新規ルール追加ではなく、既存handoffと検証ルールの意味を明確にする置換である。
