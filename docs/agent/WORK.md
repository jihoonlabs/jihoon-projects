# AGENTS改善 WORK

## Version
v2.1 candidate re-review

## Goal
実作業と独立reviewの結果から、AGENTS.mdを増やさずに自律性・統合安定性・引継ぎ精度を改善する。

## Evidence
- v2を基準に複数の独立review候補を比較した。
- 実作業ではChild単体の成功とParent統合後の成功が一致しないケースがあり、共有境界・接続点・親範囲の回帰確認が必要だった。
- 広すぎる停止条件は、古いMD、無関係なdirty状態、既存パターンから解ける小判断でもAIを止める可能性がある。
- 特定のClaude/Codex/IDEではなく、Gitと作業MDを共通状態として異なるAI環境が参加できる運用を優先する。

## v2.1 decisions
- 1責任単位と必要時のみ分割する原則は維持する。
- 分解は上位→下位、統合・検証は下位→上位とする。
- Child handoffに検証結果・残る制約/未検証条件・commit SHAを使い、Parentが採用SHAと最終統合状態を所有する。
- 「複数の妥当案」「不確実性」「文書と実装の矛盾」だけで即停止せず、既存コード・テスト・契約から安全に解消できる範囲は自律判断する。
- 無関係なdirty/untrackedは保護するが、それ自体を全作業停止理由にはしない。
- 検証は変更に最も近いテストから開始し、影響範囲に応じて段階的に広げる。
- AGENTS改善サイクルは通常作業の常時ルールから外し、必要時に独立したreview作業として扱う。
- 特定モデル、IDE、固定ファイル数、固定コンテキスト量、常時フルテスト等の未検証な制約は追加しない。

## Re-review judgment
- Childの残制約・未検証条件は、別AIや別環境へ渡す際に「検証済み」の誤解を防ぐため、handoff情報として追加する価値がある。
- 段階的な検証は安全性を落とさず通常作業のコストを下げるため採用する。統合時の接続点・親範囲回帰は別途維持する。
- commit SHA管理は現状で十分。Parentが各Childの採用SHAと統合状態を持てば、異なるAI環境でも同じ成果物を特定できる。Parent自身のSHAを毎回MDへ追記する規則は履歴重複になるため追加しない。
- Git安全性は現状で十分であり、未経験の事故を想定した追加禁止事項は増やさない。
- 確認条件は第1節へ集約し、統合節で広い「設計判断」を重ねて停止条件を増やさない。

## Validation target
次の新規作業から、以下を観察する。
- 不要な質問・停止が減るか
- Child→Parent統合時の取りこぼしが減るか
- 引継ぎ時に採用SHA・検証状態・残る制約が明確か
- 検証コストが変更影響に見合っているか
- 規則自体のcontextコストが増えないか
