# AGENTS改善 WORK

## Goal
AIに多くの規則を覚えさせるのではなく、作業責任とコンテキストを小さく保ち、検証可能な境界で安全に自律作業できる状態を作る。

## 判断基準
- **分業**: 1 Child = 1つの独立して検証可能な責任。機能数を減らすのではなく、AIが同時に考える責任を減らす。
- **Context**: AGENTSは共通ルール、親MDはRouter/統合契約、Child MDは現在作業だけを所有する。履歴はGitへ任せる。
- **自律性**: リポジトリから確認できることや確定方針の実装で止まらない。新しい意思決定だけユーザーへ戻す。
- **統合**: Child単体の成功より、境界・契約・接続点・親回帰を重視する。
- **検証**: プロンプト規則だけに頼らず、既存CI/script/hookを使う。反復して実害が出る規則だけgate化する。
- **安全**: 他作業・dirty state・mainを保護し、破壊的なGit操作は暗黙に行わない。

## v2で見つかった改善点
1. AGENTS自身の改善手順まで常設ルールにすると、全作業へ不要なメタ作業を持ち込む。改善サイクルはこのWORK側で管理する。
2. 「想定外なら停止」は広すぎる。安全上の衝突と、AIが自律調査で解決できる不確実性を分ける。
3. 「必要なテストを全部実行」ではコストが膨らみやすい。変更に近い検証から広げ、統合時に接続点と親回帰を確認する。
4. Child分割は有効だが、統合契約が弱いと局所最適が増える。親MDには履歴ではなく境界・依存・統合前提を残す。
5. gate/harnessは有効だが、規則ごとにhookを増やすと別の複雑性になる。実際に繰り返す失敗を優先して機械化する。

## 継続方法
実作業で同じ失敗や摩擦が繰り返された時だけ候補をここへ追加する。
AGENTS変更は独立した改善作業で比較・検証し、ユーザー承認後に次の作業から適用する。
