# AGENTS review candidate

## Goal
`docs/agents-v2` を基準に、常時コンテキストを減らしながら自律性・Git安全性・Child統合品質を維持する独立候補を作る。

## Findings
- v2は安全性を広くカバーしているが、AGENTS改善手順まで常時ルールに入り、通常開発には不要なコンテキストがある。
- WORK/MANUALとAGENTSで同じ方針が反復され、どこが実行規則か分かりにくくなりやすい。
- 「必要なコードだけ読む」は強く解釈すると依存・テスト・設定の探索を抑え、逆に固定的な全読みにするとcontext bloatになる。開始範囲だけ小さくし、必要性に応じた探索を許可する方が安定する。
- Child単体の成功と統合成功は別物。共有契約と接続点、親範囲の回帰を統合側の責任として明示する必要がある。
- 確認条件が広いとAIが小さな判断でも停止する。既決定範囲は自律実行を既定とし、結果を変える未決定事項と危険なGit状態だけを停止条件にする。

## Candidate policy
- AGENTSは常時必要な「開始・自律境界・分業統合・Git・検証・文書」のみ。
- AGENTS改善サイクルの詳細はAGENTSから外し、保守原則1項に圧縮。
- WORKは候補検討の根拠を残す場所であり、通常作業の追加ルールにしない。
- MANUALは候補比較用の人間向け要約に限定する。

## External comparison
- OpenAIの近年の運用例は、巨大なAGENTSではなく短い索引と必要時に読むrepository knowledgeを推奨している。
- Codexは階層AGENTSを自動注入するため、常時ルールの肥大化は直接context costになる。
- 公開AGENTSの実例でも、具体的な境界・検証・Git制約を短く明示するパターンが有効。一方、汎用的な「良いコードを書く」等は採用しない。
- 複雑作業用のExecPlanは有用だが、現在のEpic/Child作業MDが同じ役割を担うため、新しい計画文書は追加しない。
