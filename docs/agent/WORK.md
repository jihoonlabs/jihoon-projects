# AGENTS改善 WORK

## Goal
実作業で再発した摩擦だけを候補化し、AGENTSを最小の恒久ルールに保つ。

## Current findings
- Epic文書に完了Childの実装・検証履歴が蓄積し、Routerが再び大きなコンテキストになりやすい。
- Child単体の検証が強くても、統合時の共有境界・前提・接続点が明示されないと親での不具合を防げない。
- 「不確実なら確認」を広く解釈すると、既存パターンで解ける実装判断までユーザー待ちになりやすい。
- 毎回の全体検証は安全性より待ち時間を増やす場合があり、変更近傍から影響範囲へ広げる方が効率的。

## Candidate policy
- AGENTSには複数作業で再発し、削除すると実害が出る恒久ルールだけを入れる。
- プロジェクト固有の状態・履歴・一時的な手順は各作業MDまたはコード/テストに置く。
- 改善候補がない作業ではAGENTS関連文書を更新しない。
- AGENTS変更はユーザーが明示的に依頼・承認した作業だけで行う。

## Next review
次の実作業で同じ問題が再発した時だけ、この候補を更新する。
