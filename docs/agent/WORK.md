# AGENTS改善 WORK

## Version
v2.1 candidate independent re-review

## Goal
実作業と独立reviewの結果から、AGENTS.mdを増やさずに自律性・統合安定性・引継ぎ精度を改善する。

## Evidence
- v2.1の「止めすぎない」「Child SHA handoff」「Parentが統合状態を所有」「無関係なdirtyで停止しない」という方向は維持価値が高い。
- Child単体で検証済みでも、環境依存・未実行条件・既知制約がParentで見えないと統合判断を誤るため、handoffには未解消条件も必要。
- 検証を常にフルで行う規則は重く、局所テストだけで終える規則は統合回帰を逃す。変更に近い検証から影響範囲へ広げる方が両方を避けやすい。
- 特定AIの高い推論能力を前提にせず、Git・コード・テスト・作業MDから同じ判断材料を取得できる形を優先する。

## Re-review decisions
- v2.1の大構造、上位→下位の分解、検証済み下位→上位の逆順統合は維持する。
- Child handoffに検証結果だけでなく残る制約・未検証条件を加える。
- Parentは採用SHAだけでなく、そのSHAに付随する未解消条件と最終統合状態を所有する。
- 検証は変更に最も近いものから開始し、影響範囲に応じて段階的に広げる。
- 「対象ファイル一覧」より承認済み責任・仕様を変更境界として扱い、明白な接続修正で不要に停止しない。
- context規則は重複を減らし、現在作業から必要時に追加探索する一方向に統一する。
- root AGENTSの言語・コメント規則は今回削除しない。既存repository共通規約として運用実績があるため、scope分離は別の実作業根拠が出た時に判断する。

## Not adopted
- Child handoffに固定テンプレートや必須フィールド数を追加すること。
- commit SHAだけで統合完了を自動判定すること。
- 毎回full suite、ブラウザ確認、特定IDE機能を強制すること。
- 将来起こるかもしれない競合・並列実行問題を先回りして新規ルール化すること。

## Validation target
次の新規作業から、以下を観察する。
- 不要な質問・停止が減るか
- Child→Parentで制約・未検証条件の取りこぼしが減るか
- 採用SHAと実際の統合状態の対応が明確か
- 検証時間と回帰検出のバランスが改善するか
- 規則自体のcontextコストが増えないか

## Application
比較review用候補。原本 `docs/agents-v2` と `main` は変更しない。
