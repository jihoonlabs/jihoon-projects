# AGENTS改善 WORK

## Version
v2.1

## Goal
実作業から得た改善候補を必要な時だけ集約し、AGENTS.mdを増やさずに自律性・統合安定性・引継ぎ精度を改善する。

## Operating policy
- 各作業AIはAGENTS改善点を探すことを目的にしない。本来の作業を優先する。
- 実作業中に効率・安定性・統合・context・Git・検証の改善点が明確に見えた場合だけ、理由と実例を添えて報告する。
- 改善点がなければ報告不要とする。候補数を増やすための提案はしない。
- 報告された候補はこのAGENTS専用作業でまとめ、必要に応じて公式coding-agent情報・公開事例と比較する。
- 定期確認は「変更のため」ではなく「変更が必要かの確認」とする。根拠がなければ更新しない。
- 大きな構造変更でなければv2.xとして更新し、構造自体が変わる時だけ次のmajor versionを検討する。

## v2.1 decisions
- 1責任単位と必要時のみ分割する原則を維持する。
- 分解は上位→下位、統合・検証は下位→上位とする。
- Child handoffには結果・境界・依存/前提・検証結果・残る制約/未検証事項・commit SHAを含め、Parentが採用SHAと最終統合状態を所有する。
- 既存コード・テスト・契約から安全に解消できる小判断は自律判断する。
- 無関係なdirty/untrackedは保護するが、それ自体を全作業停止理由にはしない。
- 検証は変更に近いものから開始し、影響範囲に応じて広げる。
- 特定モデル、IDE、固定ファイル数、固定context量、常時フルテスト等の未検証な制約は追加しない。

## Review trigger
実作業から改善候補が報告された時、または定期確認で外部の重要な変化が確認された時だけ再検討する。
