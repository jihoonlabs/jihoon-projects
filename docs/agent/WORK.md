# AGENTS改善 WORK

## 目的
AGENTS.mdを恒常的に増やすのではなく、実作業で繰り返し発生した摩擦だけを改善候補として検証する。

## 採用基準
候補は次のいずれかを満たす場合だけ残す。
- 同種の失敗・停止・過剰探索が繰り返される。
- Git安全性または統合品質を明確に改善する。
- 複数プロジェクトで常時必要な判断基準である。

単発の作業手順、特定機能の知識、コードから取得できる情報はAGENTSへ入れない。

## 現在の観察
- Childを小さくするだけでは統合品質は上がらない。共有境界・依存関係・接続点の検証が必要。
- 「必要なコードだけ読む」を固定的な禁止として扱うと、関連テストや設定の発見が遅れる。開始文脈は小さくし、証拠に応じて探索範囲を広げる方が安定する。
- 不確実性を広く停止条件にすると、コードや既存仕様から解決可能な判断でもユーザー確認が増える。成果を変える決定だけを承認境界にする。
- 全チェックを毎回実行するより、変更箇所に近い検証から統合リスクに応じて拡張する方が効率的。
- 作業MD、MANUAL、AGENTSに同じ方針を重複させるとcontext bloatと更新ずれが生じる。

## 運用
改善確認は作業の区切り、または実際の失敗が規則不足を示した時だけ行う。候補がなければ更新しない。
AGENTSへの反映はユーザー承認後に行い、進行中作業へ遡及適用しない。
