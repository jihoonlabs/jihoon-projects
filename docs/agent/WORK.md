# AGENTS review WORK

## Goal
`docs/agents-v2`を基準に、常時コンテキストを増やさず、実作業の自律性・Git安全性・Child統合品質を上げる候補を作る。

## Findings
- v2は最小化の方向は正しいが、AGENTS改善サイクル自体をAGENTSへ入れており、通常作業にも不要なメタ指示が毎回入る。
- 「新設計・構成・UX」「範囲外変更」など停止条件が広く、既存実装から安全に決められる局所判断でも質問を誘発しやすい。
- Childの契約と統合後検証は定義されているが、複数Childの接続不具合を誰が所有するかが弱い。親が最終統合状態を所有する必要がある。
- リポジトリはLaravel/React等の複数境界を持ち、Ticketのようにバックエンド・フロントエンドを跨ぐため、Child単体テストだけでは共有契約の回帰を捕捉できない。
- 文書はWORK/MANUAL/各プロジェクトMDへ増えやすい。コードから再取得できる履歴や同じ説明の複製はcontext bloatになる。

## Decisions
- AGENTSは「開始時の探索」「停止条件」「Child統合」「検証/Git」「文書」の5領域だけに縮約する。
- 固定ファイル一覧ではなく、最小コンテキストから必要性に応じて探索を広げる。
- 可逆な局所判断はAIに委ね、ユーザー確認は契約変更・実質的scope拡大・破壊的操作・製品判断へ限定する。
- Child統合では親をintegration ownerとし、接続点と親の完了条件を検証する。単体テストの全再実行を目的化しない。
- AGENTS改善方法や今回のrollout説明は常時注入せず、このreview文書側に置く。

## External comparison
- OpenAIの最近の運用はAGENTSを百科事典ではなく短い目次/ナビゲーションとして扱い、詳細は必要時に取得する方向。
- 新しいモデル向けガイドも、過去に積み上げた手順やscaffoldingを見直し、不要な指示を削ることを推奨している。
- 公開AGENTS事例はcontext制限、Git安全性、検証を重視するが、具体的なbyte cap等はこのリポジトリ固有の必要性が確認できないため採用しない。

## Validation
- 原本 `docs/agents-v2` から独立reviewブランチを作成。
- mainおよび原本ブランチは変更しない。
- 文書のみの変更のためコードテストは不要。最終diffで変更対象を3文書に限定して確認する。
