# AGENTS v2.2 업그레이드 초안 및 가이드

이 문서는 기존 v2.1의 3분할 구조(AGENTS, WORK, MANUAL) 철학을 유지하면서, 다중 에이전트 협업 시 발생하는 컨텍스트 누수와 통합 충돌을 방지하기 위해 실무 검증된 3가지 개선점을 반영한 v2.2 초안입니다.

---

## 1. AGENTS-v2.2.md (AI 작업 규칙 본체)
> **변경 요약**: [제2항]에 Handoff 규격 및 반송(Reject) 규칙 추가, [제1항/4항]에 명시적 보고 트리거 추가.

### 1. 基準 (기준)
- 이 규약은 적은 컨텍스트로 안전하고 효율적인 자율 작업을 하기 위한 최소 필수 룰이다. 규칙 추가보다 간결화·통합을 우선한다.
- 시작 시 현재 브랜치, git status, AGENTS.md, 현재의 작업 MD, 필요한 대상 코드를 확인한다.
- 1작업 단위는 독립적으로 구현·검증할 수 있는 1책임으로 제한하며, 수반되는 부가 수정이나 명백한 회귀(Regression) 수정은 같은 범위에 포함한다.
- 확정 방침의 구현·테스트·명백한 버그 수정 및 기존 패턴에서 유추 가능한 작은 판단은 자율적으로 진행한다.
- 신규 사양, UX, 공개 API, 데이터 모델, 아키텍처 변경 등 결과가 실질적으로 바뀌는 판단이나 안전하게 해소할 수 없는 모순이 있을 때만 영향을 정리해 사용자에게 확인한다.
- **[추가]** 동일한 검증(Lint/Test) 에러로 3회 이상 수정이 반복되거나, 통합 단계에서 계약 충돌이 발생한 경우에만 예외적으로 그 원인을 현재 작업 MD(WORK)의 '개선 후보'에 단문으로 기록한다.

### 2. 分割と統合 (분할과 통합)
- 1작업 단위로 안전하게 완결할 수 없으면 책임별로 분할(Parent-Child)한다. Parent MD는 각 Child의 책임, 상태, 통합 계약만 Router로서 유지하고 상세를 중복시키지 않는다.
- **[추가/구체화]** Child는 Parent로 컨텍스트가 넘어갈 때 오버헤드를 막기 위해, 작업 MD에 다음 형태의 간결한 Key-Value 포맷으로 Handoff를 남긴다.
  * `SHA:` (커밋 해시)
  * `Boundary:` (변경 파일/디렉터리 경계)
  * `Contract:` (달성한 인터페이스/결과)
  * `Verification:` (실행한 검증 및 결과)
  * `Constraints:` (남은 제약 및 미검증 사항)
- Parent로 통합하는 것은 검증을 마친 Child뿐이며, Parent MD가 최종 채택 SHA와 통합 상태를 소유한다. 
- 분해는 상위에서 하위로, 통합은 검증된 하위에서 상위로 진행한다. 통합 시 연결점과 Parent 범위의 회귀를 검증하며, merge 성공만으로 완료로 치지 않는다.
- **[추가]** 통합 후 회귀 또는 연결 실패가 발생하여 단순 수정으로 해결되지 않을 경우, Parent는 임의로 Child의 코드를 수정(오염)하지 않고 즉시 해당 SHA 채택을 취소(Revert)한 뒤 실패 로그와 함께 Child로 작업을 반송(Reject)한다.

### 3. コンテキストとMD (컨텍스트와 MD)
- 작업 문서는 AI용 작업 MD(WORK)와 사용자용 MANUAL로 나눈다. 작업 MD는 목표, 범위, 제외 대상, 필요 문맥, 완료 조건, 검증, 현재 상태를 간결히 유지한다.
- MANUAL은 코드 리딩 없이도 작업 이유, 결과, 구현 개요, 검증 근거, 제약 상태를 파악할 수 있게 짧게 쓴다.
- 작업 MD는 `docs/<project>/` 산하에 둔다. 시작 시 기본 컨텍스트(AGENTS, 현재 작업 MD, 대상 코드)만 유지하며, 이유 없이 부모/형제/과거 작업을 가져오지 않는다.
- Git, 코드, 테스트를 구현 사실의 정본(Single Source of Truth)으로 삼는다. MD에는 판단, 설계 의도, 제약 등 코드에서 알기 어려운 정보만 남긴다.

### 4. 検証 (검증)
- 변경에 가장 가까운 유효 검증부터 시작해 영향 범위에 따라 Lint, 타입 체크, 빌드 등으로 넓힌다. 실패 시 변경과의 인과를 확인하고 책임 범위 내라면 수정 후 재검증한다.
- 미실행은 '미검증'으로 취급하며, 완료 전 최종 diff와 git status를 확인한다.
- 검증 완료, 미검증, 미완성을 엄격히 구분하고 보고를 실태보다 선행시키지 않는다.

### 5. Gitと変更権限 (Git과 변경 권한)
- 현재 책임에 직접 필요한 파일만 변경한다. 범위 외 변경이 필요하면 보류하고 이유를 보고한다.
- 타 주체가 변경 중인 파일이나 기존 dirty/untracked 상태는 명시적 승인 없이 변경/삭제/덮어쓰기/stash/reset 하지 않는다.
- 무관한 Git 상태 충돌이나 브랜치 불일치는 임의 해소하지 않고 보고한다.
- 승인 범위 밖의 브랜치 조작, 병합, 커밋, 푸시, 워크트리 생성은 금지한다.
- AGENTS.md는 최우선 규칙이며 AI가 독자적으로 무시/변경하지 않는다.

### 6. 言語とコメント (언어 및 주석)
- 비자명한 분기나 비즈니스 로직에만 짧은 주석을 남기고 자명한 설명은 생략한다.
- 기존 영어 주석은 불필요하게 변경하지 않으며, 일본어화가 필요한 문장은 자연스럽게 작성한다. (새로운 한국어 주석/문서 작성 금지).

## 2. WORK-v2.2.md (업데이트 요약용 참고)
> **변경 요약**: 개선점 보고에 대한 구체적 기준 추가

### Version
v2.2

### Goal
기존 v2.1의 1책임 단위, 컨텍스트 분리 철학을 유지하면서, Child-Parent 통합 과정의 상태 오염을 방지하고 개선 후보 발굴의 객관적 기준을 도입한다.

### v2.2 decisions (추가된 사항)
- **Handoff 정형화**: 토큰 낭비와 의사소통 오류를 막기 위해 Child의 Handoff는 규격화된 Key-Value 리스트 구조를 강제한다.
- **반송(Reject) 원칙**: 통합 검증 실패 시 Parent 에이전트 컨텍스트 내에서의 무리한 땜질(마개조)을 금지하고, 즉시 SHA를 폐기한 뒤 하위 작업으로 돌려보낸다.
- **정량적 회고 트리거**: "개선점이 명확히 보일 때"라는 모호한 조건을 "동일 에러 3회 반복" 또는 "통합 계약 충돌 시"로 명확히 하여, 무의미한 보고를 없애고 실질적인 개선 데이터만 수집한다.
