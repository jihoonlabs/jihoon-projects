# 作業報告（MANUAL）の書式 v2.1

作業の完了時に書く、ユーザー向けの短い報告です。コードやWORKを読み直さなくても、なぜ・何を・どう変え、何で確認したかが分かるようにします。

```md
# <作業名>

## 目的
<1〜2行>

## 変更内容
## 実装概要
## 検証
- 確認したこと / 方法 / 結果
## 影響・制約（ある場合のみ）
## 状態
<完了 / 一部完了と残りの作業>
```

## 記入例

> **チケット更新競合への対応**
>
> **目的:** 複数人が同じチケットやボードを操作したとき、古い画面からの更新で最新の変更を上書きしないようにする。
>
> **変更内容:** チケットに `version`、プロジェクトに `board_version` を追加し、保存・移動時に画面が持つ値と照合する。不一致の場合は409を返し、画面で最新情報の再取得を促す。
>
> **実装概要:** チケット保存はバージョン比較と更新を1つのSQLで行う。ボード移動はプロジェクト行をロックしてから `board_version` を比較し、列内の並び順を書き直す。
>
> **検証:** Laravelの `EditConcurrencyTest`・`BoardOrderTest`、ReactのTicketModal競合復旧テスト。2026年10月27日の公開デモ時点でGitHub Actionsの全テストが通過。
>
> **状態:** 完了。
