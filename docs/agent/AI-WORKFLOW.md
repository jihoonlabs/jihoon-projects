# AIを活用した開発プロセス

生成AIを「速く書く道具」ではなく、品質を保ったまま作業を任せられる開発体制として設計・運用しています。人が判断すべきことだけを人に残し、それ以外は仕組みで担保することを目指しています。

## 設計の方針

| 課題 | 方針 |
| --- | --- |
| AIは自分の出力を正しいと判断しがち | 実装したAIとは別のモデルが完了条件とテストで検証し、通過したcommitだけを採用する |
| AIにレビューを頼むと、問題がなくても指摘を作る | 指摘はそのまま反映せず、項目ごとに採用・却下・保留を判断する。根拠を示せる指摘だけを反映する |
| 指示ファイルは長くなるほど守られない | 規則は最小限に保ち、実際に起きた失敗から必要なものだけを足す。追加より統合・削除を優先する |
| 文章の規則は読み飛ばされる | 作業ブランチや担当範囲の取り違えをフックで止める仕組みを導入する。ただしサーバー側の保護の代わりにはしない |
| 会話をまたぐと状態が失われる | 作業ごとのWORKに目標・完了条件・検証結果・次の行動を残し、会話の記憶ではなくGitとWORKから再開する |

## 作業の流れ

1. 作業を独立して完了できる責任単位に分け、WORKに目標・範囲・完了条件を書く
2. 実装AIがブランチで実装し、変更に近いテストから確認する
3. 別モデルの検証AIが、完了条件・差分・テストをもとに判定する。未実行の検証は未検証として残す
4. 複数の作業は検証済みのものだけを統合し、統合後も接続点と回帰を別のAIが確認する
5. ユーザー向けの完了報告（MANUAL）を残す

新しい仕様、UX、公開API、データモデルに関わる判断はAIに任せず、影響と推奨案を添えて人が決めます。

## 規則の改善

規則は作業のたびに変えず、実作業で見つかった問題を候補として記録し、月に一度ほど公式情報や公開事例と照らし合わせて見直します。根拠のない好みや一度きりの問題では規則を変えません。

規則の変更は、人が内容を確認して承認したものだけを反映します。

## 公開範囲

運用中の規則、フック、作業記録は非公開で管理し、継続的に更新しています。このリポジトリでは、その出発点となった [AGENTS v2.1](AGENTS-v2.1.md) と、作業記録の書式（[WORK](WORK-v2.1.md)・[MANUAL](MANUAL-v2.1.md)）を公開しています。
