# AGENTS v2.1 独立レビュー

レビュー日: 2026-10-07
対象: `docs/agents-v2` v2.1 candidate

## 結論
v2.1はv2より明確に良い。特に「止めすぎない」「Childの検証済みSHAをhandoffする」「Parentが採用SHAと統合状態を所有する」「無関係なdirty状態だけで停止しない」は採用を推奨する。

ただし正式v2にする前に、root `AGENTS.md`はもう一段だけ役割を狭められる。

## 採用推奨
- 承認済み範囲では既存コード・テスト・契約から解ける小判断を自律処理する。
- 新仕様、UX、公開API、データモデル、構成、責任範囲を変える時だけユーザー判断へ戻す。
- Childは検証結果とcommit SHAをhandoffし、Parentが実際の採用SHAと統合状態を所有する。
- merge成功を完了とせず、共有境界・接続点・親範囲の回帰まで検証する。
- 無関係なdirty/untrackedは保護しつつ、作業停止理由にはしない。
- AGENTS改善を通常作業の常時ループから外す。

## 正式v2前の追加提案

### 1. root AGENTSから作業固有ルールをさらに分離
現在の「作業MDとMANUALの詳細な役割」と「Webポートフォリオの言語・コメント規則」は全作業で必要な不変条件ではない。
rootにはnavigation、approval boundary、Git safety、integration、validationだけを残し、文書形式やプロジェクト固有言語規則は対象scopeのMDまたは下位AGENTSへ置く方がよい。

### 2. 開始時の必読を固定しすぎない
「必要な対象コードを確認する」は妥当だが、単純な変更でも毎回コード読込を義務化する文面にはしない。
branch/status/AGENTS/現在作業の契約を起点に、タスクに必要な証拠だけ探索する、と表現する方がcontext costを抑えられる。

### 3. 「範囲外ファイル」の扱いを責任基準にする
v2.1には「現在の責任に直接必要なファイルだけを変更」「範囲外変更が必要なら変更せず報告」が残っている。
統合や明白な回帰では責任完了に必要な接続ファイルが当初一覧外になることがあるため、ファイル一覧より責任・承認済み仕様を境界にする方が停止を減らせる。
ただし既存dirty/untracked、他作業者の変更、公開契約変更は従来通り保護する。

### 4. 検証はrisk-based escalationを明示
「責任範囲に応じたテスト」は正しいが、近いテスト→関連チェック→統合回帰の順に広げる原則を一文で示すと、毎回full suiteを回す過剰検証と、局所テストだけで終える不足検証の両方を避けやすい。

## 削除・移動候補
- root AGENTSの「Webポートフォリオでは韓国語を使わない」: 対象プロジェクトscopeへ移動。
- root AGENTSのコメント方針: リポジトリ全体の本当の共通規約なら維持、そうでなければscopeへ移動。
- MANUALの詳細フィールド定義: 作業テンプレート側へ移動し、rootでは「実行事実を計画として報告しない」だけ残せば十分。

## 判断根拠
最近のcoding agentは、巨大な常時instructionより短いrepository mapと必要時に読むsource of truthで性能が安定する方向に進んでいる。
したがってAGENTSは「AIに何を全部教えるか」ではなく、「何を常に守らせ、どこから必要情報を探させるか」を定義する方がよい。

v2.1はこの方向へかなり近づいているため、大規模な再設計は不要。正式v2前には上記のscope整理とrisk-based validationだけ追加検討することを推奨する。
