# Ticketボード更新競合 — WORK例

> 公開コード・テストをもとに作成したポートフォリオ用の作業例です。過去の内部WORKや実運用手順を転載したものではありません。

## 目標

古い画面からのチケット移動が、同じボードに加わった新しい変更を上書きしないようにする。

## 範囲

- ボード移動リクエストで、画面が保持する `board_version` をサーバーと照合する。
- バージョンが古い場合は移動を拒否し、チケットとボードの状態を保持する。
- 認証・権限設計や、競合時の画面デザイン変更は対象外とする。

## 完了条件

- 現在のバージョンを使う移動が成功し、新しいボードバージョンを返す。
- 古いバージョンの移動はHTTP 409で拒否され、チケットの状態・位置とボードバージョンが変わらない。
- 成功・拒否の両方を自動テストで確認できる。
