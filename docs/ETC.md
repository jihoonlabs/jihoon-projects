# 🚀 [AI 학습용 Context] 일본 IT 자사개발 이직 로드맵

> 이 문서는 이후 대화에서 구직 조언을 개인 상황에 맞게 하기 위한 참고 자료다. 확인되지 않은 사실을 확정하지 말고, 사용자 설명과 공개 정보를 구분한다. 플랫폼 추천을 기업의 직접 관심으로 오해하지 않는다.

---

## 1. 사용자 프로필과 목표

- 일본에서 웹 프론트엔드 엔지니어로 약 6년 실무. 주력은 Vue.js / Nuxt.js / TypeScript.
- Vitest 테스트 기반 정비를 전담했고, 권한·기능 설정·신청 상태별 화면 분기, Mock/Stub API, 비동기 흐름, 회귀 방지 테스트를 실무에서 수행했다.
- React / TypeScript와 Laravel 앱의 운영 보수·기능 수정 경험이 있다. 개인 GitHub에서는 React + Laravel 티켓 관리 앱을 개발하고 테스트 품질을 실무 수준으로 높이는 중이다. 개인 개발과 실무 경력을 분리해 설명한다.
- 이전 업무에서 GitHub 연동 AI 도구를 코드 리뷰와 품질 개선에 사용했다고 사용자가 설명했다. 개인 개발에서는 AI 에이전트를 개발 보조에 활용하고 작업 절차를 문서화한다. AI 엔지니어 경력으로 과장하지 않는다.
- 현재 株式会社キャリアデザインセンター 소속(2026년 7월 입사). 배치 대기와 경력에 맞지 않는 금융권 Java 안건 제안을 받았다고 설명했다. Java 실무 경험은 없고 주력은 프론트엔드다.
- 파견 중심이 아닌 자사 제품 또는 제품 개발 조직에서 프론트엔드 전문성을 살리며, 기술 성장과 보상을 추구한다.
- 리모트 중심을 선호한다. 장거리 통근과 건강 부담을 고려하되, 공고별 출근 일수와 실제 운영을 확인한다.
- 과거 프리랜서 수입보다 크게 낮은 보상은 원하지 않는다. 연봉 총액뿐 아니라 월 기본급, 보장 상여, 변동 상여, 고정 잔업수당과 시간을 구분한다.

## 2. 보상 판단 기준

- 현재 연봉은 474만 엔으로 사용자 제공 스킬시트에 기재되어 있다.
- 현재의 경력·실무 성과·GitHub 포트폴리오를 함께 고려해, **도쿄 자사 제품 프론트엔드 정규직에서 600만 엔 전후를 목표로 협상해볼 근거가 있다**고 본다. 600만 엔 이상을 보장하거나 모든 회사가 그 수준으로 평가할 것이라고 단정하지 않는다.
- 적합한 역할에서 600만 엔을 우선 목표로 제시하되, 고정 지급액·업무 범위·리모트·성장성을 함께 비교한다. 550만 엔대가 자동으로 실력의 상한이라는 식으로 말하지 않는다.
- 650만 엔 이상은 리드 책임, 기술 의사결정, 제품 도메인 적합성, 회사 급여 밴드에 따라 상향 도전할 수 있다.
- 오퍼 비교 시 다음 항목을 분리해 확인한다.
  1. 월 기본급과 연간 고정 지급액
  2. 고정 잔업수당 포함 여부와 시간, 초과분 지급
  3. 상여금이 보장인지 실적 연동인지, 첫해 산정 방식
  4. 성과급·스톡옵션을 제외한 확정 연봉
  5. 연봉 인상·평가 주기와 수습 기간 조건

## 3. 구직 채널 운영

사용자는 **Findy, Green, LAPRAS에 등록 완료**했다. 재등록을 권하지 말고 프로필 점검과 실제 활동을 돕는다.

### Findy
- GitHub 기반 스킬 편차치는 참고 지표이며 테스트 설계와 업무 성과 전체를 대변하지 않는다.
- 기업의 ‘いいね’/스카우트, 사용자의 ‘いいかも’, 플랫폼 자동 공고 추천을 구분한다.
- 자동 추천 메일은 기업이 사용자를 선택했다는 뜻이 아니다. 공고 상세를 보고 관심 있으면 ‘いいかも’를 보낸다.
- 프로필에 최근 GitHub 활동, 공개 프로젝트, Vue/Nuxt·TypeScript 실무 및 품질 개선 성과가 제대로 표시되는지 확인한다.
- MNTSQ 프론트엔드 공고는 Vue 경험과 접점이 있지만 월 5일 이상 출근하는 하이브리드로 안내되어 있다. 풀리모트가 아니며, 지원 전 실제 조건을 확인한다.

### Green
- 프로필을 정리하고 조건에 맞는 공고를 능동적으로 찾는다. ‘気になる’와 지원 기능을 활용한다.
- ‘気になる’가 면담 확약이나 채용 제안은 아니며, 회신과 전형은 별개다.

### LAPRAS
- GitHub 등 공개 기술 활동과 프로필을 최신화한다.
- 자동 생성된 경력·기술이 정확한지 확인한다. 점수는 참고로만 쓰고 프론트엔드 경력과 테스트 전문성은 직접 기술한다.

### 공통 원칙
- 플랫폼에 등록만 하고 기다리지 않는다. 맞는 공고를 골라 관심 표시와 지원을 진행하고, 기업 직접 연락과 추천을 구분해 기록한다.
- 하루 10건 같은 근거 없는 할당량은 두지 않는다. 가능한 시간에 지속 가능한 빈도로 조건에 맞는 공고를 선별한다.
- 플랫폼 경로가 회사 공식 채용 경로보다 항상 유리하다고 가정하지 않는다. 플랫폼 매칭을 활용하면서, 잘 맞는 공고는 공식 경로도 비교한다.
- 필수 요건, 실제 직무 범위, 근무 방식, 고정 보상, 전형(과제·코딩 테스트 포함)을 확인한 뒤 지원 여부를 정한다.
- 주력은 Vue/Nuxt 프론트엔드 자사 제품 포지션. React/TypeScript, Laravel, AI 제품 개발은 실제 업무 범위가 경험과 맞는 경우 선별한다. ‘풀스택’ 직함만 보고 지원하지 않는다.

## 4. 서류와 면접 포지셔닝

> Vue.js / Nuxt.js 실무 약 6년의 프론트엔드 엔지니어. TypeScript 기반 개발, 테스트 기반 정비와 회귀 방지를 강점으로 한다. React / Laravel 운영 보수 경험과 개인 개발로 적용 범위를 넓히고 있다. AI 도구는 업무 코드 리뷰·품질 개선 및 개인 개발 보조에 활용해 왔다.

- 실무와 개인 프로젝트를 명확히 구분한다.
- 현재 직장 업무는 스킬시트에 적힌 범위까지만 설명한다.
- GitHub는 연수와 동등한 경력으로 환산하지 않지만, 설계·구현·테스트·실패 복구를 직접 수행할 수 있다는 역량 증거로 평가한다.
- 현 직장이나 영업 담당자를 비난하기보다, 프론트엔드 전문성과 제품 개발로 이동하려는 목표를 중심으로 이직 사유를 설명한다.
- 개인 프로젝트에서는 기능 목록뿐 아니라 문제 정의, 설계 결정, 테스트 전략, 실패·복구 처리, AI 결과를 검토·검증하는 방식을 보여준다.

## 5. 집에서 실행할 구직 계획

### 첫날: 45~60분
1. Findy 알림에서 기업 직접 ‘いいね’/스카우트와 자동 추천을 구분한다. MNTSQ 공고는 상세 조건을 보고 프론트엔드 역할과 월 5일 출근을 감당할 수 있으면 ‘いいかも’를 보낸다.
2. Green에서 Vue/Nuxt, TypeScript, 프론트엔드, 자사 SaaS 키워드로 검색해 조건에 맞는 공고를 2~3개 저장한다.
3. LAPRAS 프로필의 GitHub 링크, 경력·스킬 자동 반영을 확인한다.
4. 세 사이트 프로필의 희망 직무·연봉·리모트 조건이 서로 모순되지 않는지 점검한다.

### 이후 매주
- 평일 저녁 2~3회, 30분씩 공고 확인과 지원에 사용한다.
- 매회 조건에 맞는 공고 1~3개를 골라 상세를 확인하고, 관심 표시 또는 지원을 진행한다. 숫자를 채우기 위한 무차별 클릭은 하지 않는다.
- 지원 현황을 간단히 기록한다: 회사/직무, 경로, 공고 적합도, 연봉 구조, 출근일, 지원 날짜, 회신/전형 결과.
- 2주마다 결과를 보고 병목을 조정한다. 관심 표시만 있고 회신이 없으면 프로필·공고 적합도 점검, 지원 후 서류 탈락이 반복되면 이력서·직무경력서 보완, 면담은 되지만 오퍼가 낮으면 보상 구조와 역할 범위를 재검토한다.
- 연락만 기다리지 말고 지원 활동을 이번 주부터 시작한다. 퇴사 날짜는 내정과 조건을 확인한 뒤 결정하며 특정 날짜까지 성공을 보장하지 않는다.
