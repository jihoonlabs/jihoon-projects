# 🚀 [AI 학습용 Context] 일본 IT 자사개발 이직 로드맵

> 이 문서는 이후 대화에서 구직 조언을 개인 상황에 맞게 하기 위한 참고 자료다. 확인되지 않은 사실을 확정하지 말고, 사용자가 알려준 정보와 공개 자료를 구분한다. 회사나 채용 플랫폼의 자동 추천을 기업의 직접 관심·스카우트로 해석하지 않는다.

---

## 1. 사용자 프로필 및 현재 상황

- **경력:** 일본에서 웹 프론트엔드 엔지니어로 약 6년간 실무. Vue.js / Nuxt.js가 주력이며 TypeScript, 화면 설계·구현·운영 보수 경험이 있다.
- **품질 경험:** Vitest 기반 테스트 기반 정비를 전담한 경험이 있다. 권한·기능 설정·신청 상태에 따른 화면 분기, Mock/Stub API, 비동기 흐름과 회귀 방지 검증을 실무에서 수행했다.
- **보조 경험:** React / TypeScript와 Laravel 애플리케이션의 운영 보수·기능 수정 경험이 있다. 개인 GitHub 프로젝트에서는 React와 Laravel로 티켓 관리 앱을 개발하고 테스트 품질을 계속 높이고 있다. 개인 개발과 실무 경력을 혼동해 표현하지 않는다.
- **AI 활용:** 이전 업무에서 GitHub에 연동된 AI 도구를 코드 리뷰와 품질 개선에 활용한 경험이 있다고 사용자가 설명했다. 개인 개발에서는 AI 에이전트를 개발 보조에 활용하고 작업 절차를 문서화한다. 특정 도구의 품질을 과장하거나 ‘AI 엔지니어’ 경력으로 확대 해석하지 않는다.
- **현재 직장:** 2026년 7월 입사한 株式会社キャリアデザインセンター 소속. 배치 대기 및 경력과 맞지 않는 금융권 Java 안건 제안을 받았다고 사용자가 설명했다. Java 실무 경험은 없으며 주력 분야는 프론트엔드다.
- **구직 목표:** 파견 중심이 아닌 자사 제품 또는 제품 개발 조직에서 프론트엔드 전문성을 살리고, 기술 성장과 보상을 함께 추구한다.
- **근무 조건:** 장거리 통근과 건강 부담을 고려해 리모트 중심을 선호한다. 공고별 출근 일수와 실제 운영을 확인한다. 풀리모트만 가능하다고 단정하지 않는다.
- **보상:** 과거 프리랜서 수입이 높았으므로 큰 폭의 연봉 하락은 원하지 않는다. 목표 연봉을 고정 수치로 단정하지 말고, 현재 보상·희망 조건과 공고 밴드를 함께 확인한다.

## 2. 구직 채널 운영

현재 사용자는 **Findy, Green, LAPRAS에 등록을 마쳤다.** 재등록을 권하지 말고, 프로필을 개선하고 반응을 관찰하도록 돕는다.

### Findy
- GitHub 기반 스킬 편차치는 참고 지표다. 실무의 테스트 설계·업무 성과 전체를 대변한다고 말하지 않는다.
- 기업이 보낸 ‘いいね’/스카우트와 Findy의 자동 공고 추천 메일을 구분한다.
- 공고 상세를 읽고 관심이 있으면 ‘いいかも’로 회사에 관심을 표시한다. 자동 추천은 기업이 사용자를 선택했다는 뜻이 아니다.
- 현재 MNTSQ 프론트엔드 공고는 Vue.js 경험이 우대되고, 월 5일 이상 출근하는 하이브리드로 안내되어 있다. 풀리모트는 아니다. 관심 공고로 살펴볼 수 있으나, 합격 가능성을 단정하지 않는다.

### Green
- 기업과 직접 소통하는 채널로 사용한다. 프로필을 정리하고, 경력과 조건에 맞는 공고를 선별해 ‘気になる’ 또는 지원 기능을 사용한다.
- ‘気になる’를 누르면 면담이 확약된다고 표현하지 않는다. 기업의 회신과 실제 전형은 별도다.

### LAPRAS
- GitHub 등 공개된 기술 활동과 프로필을 정리하고, 스카우트·매칭을 관찰한다.
- 점수나 진단 결과는 참고로만 다룬다. 프론트엔드 경력과 테스트 전문성을 별도로 서류에 표현한다.

### 공통 원칙
- 세 사이트는 등록 완료 상태다. 지금 할 일은 프로필 링크·조건을 확인하고, 맞는 공고에 관심 표시/지원하며, 기업 직접 연락과 자동 추천을 구분해 반응을 기록하는 것이다.
- 하루 10건, 매주 일정 면담 수 등 근거 없는 할당량을 강요하지 않는다. 지속 가능한 빈도로 품질 높은 공고를 선별한다.
- 회사 채용 페이지 직접 지원을 무조건 피하거나 플랫폼만 이용하라고 단정하지 않는다. 플랫폼을 통한 관심 표시·매칭을 우선 활용하고, 적합한 기회에는 회사 공식 채용 경로도 비교한다.
- 공고의 필수 요건, 근무 방식, 연봉, 전형(코딩 과제 포함 여부)을 확인한 뒤 지원 여부를 판단한다. 코딩 테스트를 전면 거부한다는 전제를 두지 않는다.

## 3. 서류와 면접에서 보여줄 점

### 핵심 포지셔닝

> Vue.js / Nuxt.js 실무 약 6년의 프론트엔드 엔지니어. TypeScript 기반 개발과 테스트 기반 정비·회귀 방지 경험을 강점으로 하고, React / Laravel 실무 보수 경험과 개인 개발을 통해 영역을 넓히고 있다. 업무 및 개인 개발에서 AI 도구를 활용하되, 결과를 검토하고 테스트하는 방식으로 사용한다.

### 경력 표현 원칙
- 실무 경력과 개인 포트폴리오를 명확하게 구분한다.
- React/Laravel을 개인 포트폴리오의 주된 실무 경력처럼 표현하지 않는다. 현재 직장에서의 운영 보수 경험은 스킬시트에 적힌 범위까지만 설명한다.
- AI 활용은 업무에서의 코드 리뷰·품질 개선 경험과 개인 프로젝트에서의 AI 에이전트 활용을 각각 사실에 맞게 설명한다.
- 현 직장이나 영업 담당자를 비난하는 이직 사유는 피한다. 경력 목표와 전문성을 중심으로 간결하게 설명한다.

## 4. 실행 순서

1. 등록된 Findy·Green·LAPRAS에서 프로필, GitHub 및 포트폴리오 링크, 희망 직무·근무 조건을 점검한다.
2. Findy 메일의 MNTSQ 건은 자동 추천임을 구분하고, 상세 공고의 프론트엔드 요건과 월 5일 이상 출근 조건을 확인한 뒤 ‘いいかも’를 검토한다.
3. 각 사이트에서 맞는 프론트엔드·Vue/TypeScript·자사 제품 공고를 선별해 관심 표시 또는 지원한다.
4. 회사 직접 관심/스카우트, 자동 추천, 사용자가 보낸 관심 표시, 정식 지원을 각각 구분해 기록한다.
5. 몇 주간 채널별 반응을 보고 프로필·조건·지원 전략을 조정한다. 무응답만으로 역량 부족이나 시장 전체의 평가라고 결론 내리지 않는다.
6. 퇴사 시점은 내정, 조건, 현 직장의 계약 및 퇴직 절차를 확인한 뒤 결정한다. 특정 날짜에 내정·퇴사를 맞춘다고 보장하지 않는다.
