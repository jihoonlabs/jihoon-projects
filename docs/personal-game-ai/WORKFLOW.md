# 개인 게임 AI — 단일 실행 흐름

갱신일: 2026-10-04
브랜치: feature/personal-game-ai-workflow
기준 Epic commit: b2f9132

## 목표
- 요청 파일 하나와 같은 CLI로 제작 단계를 이어간다.
- 사용자는 목표·중요한 분기·플레이 테스트를 맡는다.
- 최종 대상은 Thumby·Thumby Color·스타크래프트 리마스터 유즈맵이다.
- 사용자의 코드 붙여넣기와 전체 로그 전달 부담을 줄인다.

## 규칙
- 지침은 AGENTS.md와 이 문서만 사용한다.
- 같은 폴더 사용. worktree·AGENTS.md 수정 금지.
- 개인 AI 문서는 한국어로 작성한다.
- 기존 untracked·stash·runner_tasks.json을 보존한다.
- commit·merge는 승인 범위만 수행한다.
- push·main 통합·브랜치 삭제는 하지 않는다.

## 사용 계약
- python workflow.py --request <요청 JSON>
- 요청 필드는 goal·requirements·area이다.
- area는 기존 sandbox 또는 설정된 game 영역이다.
- 설계 검토 후 --approve-design <SHA-256>으로 이어간다.
- 테스트 검토 후 --confirm-tests <SHA-256>으로 설치한다.
- --test-feedback <텍스트 파일>로 테스트 후보를 수정한다.
- 설치 후 waiting_git에서 커밋이 필요한 테스트 경로를 안내한다.
- 테스트를 검토·커밋한 뒤 같은 요청 명령으로 구현·검사를 실행한다.
- 질문에는 --answer <작업 ID> --answer-text <답변>으로 재개한다.
- 설계·테스트 생성 중단은 --retry로 명시적으로 재시도한다.
- 설치 중단·실패한 구현·running 상태는 자동 반복하지 않는다.
- 프로그램은 Git commit·merge를 자동 수행하지 않는다.

## 구현
- workflow.py가 단계·산출물·검토 SHA를 outputs/workflow_*/state.json에 저장한다.
- 요청 파일 위치별로 기록을 사용하며 요청 내용과 문맥 변경을 차단한다.
- 같은 실행의 중복 호출을 잠금으로 차단한다.
- 상태는 임시 파일 작성 후 교체하고 상세 로그는 별도 파일로 저장한다.
- 설계·승인·후보·확정 기록과 계획의 작업 계약 변경을 확인한다.
- 실행 계획의 상태·답변은 갱신하되 대상·요청·의존성 변경은 차단한다.
- 기존 설치·Git 보호·Docker 검사·재시도·질문 후 재개를 재사용한다.
- 테스트 피드백은 이전 후보와 함께 모델에 전달하고 원본을 보존한다.
- 설계 오류에 검사 연결이 누락된 필수 조건 ID를 표시한다.

- 모의 검사로 답변 전달·실패 작업의 자동 재시도 차단을 확인했다.
- 실제 모델로 설계 실패→명시적 재시도→설계 검토→테스트 검토를 확인했다.
- 불충분한 함수 구성 검사를 피드백으로 수정하고 원본 후보 보존을 확인했다.
- 테스트 확정·설치·Git 대기→구현·Docker 검사→completed를 확인했다.
