# Ollama 대화로 Thumby 게임 작업하기

최종 목적은 로컬 Ollama로 실제 플레이 가능한 Thumby 게임을 만드는 것이다.
`game_chat.py`는 그 목적을 위한 작업 입구다. 일반 잡담 도구나 임의 셸 실행기는 아니다.
현재 첫 버전은 `ThumbyGrowth`의 상태·코드 확인, 고정 검사, 단일 실행 파일 수정을 지원한다.

## 실행

현재 checkout의 Git 변경 상태를 확인하고 `epic/thumby-growth`를 최신으로 받은 뒤 실행한다.

```bash
cd "/Users/parkjihoon/workspace/My PRJ/ai/personal-game-ai"
source .venv/bin/activate
export GAME_AI_NUM_CTX=32768
export GAME_AI_NUM_PREDICT=16384
python3 game_chat.py
```

맥에서 Ollama가 실행 중이고 `qwen3-coder:30b`가 설치되어 있어야 자연어 해석과 코드 생성이 가능하다.
위 출력 설정은 게임 파일 전체 생성에 필요한 여유를 준다. 출력 한도에 걸린 응답은 적용하지 않는다.
로컬 Ollama만 호출하며 외부 유료 모델 API를 사용하지 않는다.

## 지시 예시

- `현재 게임 상태 확인해줘`
- `rules.py 보여줘`
- `현재 게임 검사해줘`
- `전투에서 적이 경계를 벗어나는 문제를 rules.py에서 고쳐줘. 기존 조작과 저장 형식은 유지해.`

모델은 지시를 허용된 작업 하나로 해석한다. Python 실행기는 실제 파일을 읽고 기존 검사/수정 도구를 호출한다.
모델이 테스트를 실행했다고 말한 내용을 성공 증거로 사용하지 않는다.
코드 읽기는 현재 파일을 그대로 표시한다. 일반 코드 해설이나 광범위한 설계 대화는 아직 지원하지 않는다.
입력은 한 번에 2000자 이내이며 최근 네 번의 짧은 대화/실행 결과만 모델에 전달한다.

Ollama 없이 동작하는 단축 명령:

- `/status`: 실제 브랜치, 게임 경로, Git 변경, 모델 설정 확인
- `/read rules.py` 또는 `/read ThumbyGrowth.py`: 현재 코드 확인
- `/test`: Docker에서 `test_floor_movement` 실행
- `/cancel`: 대기 중인 수정 질문 취소
- `/exit`: 대화 종료

```bash
python3 game_chat.py --once /status
```

## 수정과 검사

수정 대상은 `rules.py` 또는 `ThumbyGrowth.py` 하나다. 테스트와 다른 파일은 수정하지 않는다.
현재 브랜치/작업 문맥, 허용 경로, 대상과 고정 테스트의 Git 추적·변경 상태를 확인한다.
다른 변경이 남은 대상 파일은 덮어쓰지 않는다.
Docker가 실행 중이고 `python:3.11-slim` 이미지가 이미 준비되어 있어야 한다.
도구가 자동으로 이미지를 다운로드하거나 호스트에서 후보 코드를 실행하지 않는다.
Docker 검사는 네트워크 차단, 읽기 전용 마운트, 자원 제한을 사용하는 기존 실행기로 수행한다.

수정 전 고정 검사가 통과해야 코드를 생성한다. 생성 후보는 일반 Thumby API 정적 검사와
고정 검사를 거친다. 최대 세 번의 검사/재수정 후에도 실패하면 이번 작업의 후보를 원본으로 복원한다.
모델의 추가 질문은 같은 수정 지시와 연결해 다음 답변으로 재개한다.
질문 대기 중 새 일을 하려면 먼저 `/cancel`을 입력한다. 질문 대기는 현재 대화 프로세스에서만 유지된다.
외부 편집을 발견하면 그 내용을 보존하고 중단한다. 자동 복원으로 덮어쓰지 않는다.

성공한 수정은 Git 변경으로 남는다. diff와 플레이를 확인하고 기존 Git 절차로 커밋한 뒤 다음 수정을 진행한다.
대화 실행기가 commit/push/merge나 게임 배포를 자동 수행하지 않는다.

## 기록과 한계

대화·해석·실제 결과는 `outputs/chat_<고유 ID>/turns.jsonl`에 저장한다.
검사 로그는 같은 폴더, 원본·후보·수정 검사 로그는 기존 `outputs/edit_.../`에 남긴다.
전원/프로세스 강제 종료 후 자동 재개나 전체 트랜잭션 복구는 아직 지원하지 않는다.
실행 잠금 파일이 남았다면 실제 실행 중인 프로세스와 파일/Git 상태를 확인한 뒤 처리한다.

`test_floor_movement`는 현재 바닥 이동·전투·구매·장착·저장 등을 검사하는 17개 고정 검사다.
통과는 해당 검사 범위만 의미한다. 사용자 지시 자체의 충족이나 전체 게임 품질을 증명하지 않는다.
기존 전체 게임 검사 중 9개 실패는 이전 작업에서 남아 있으며 이 도구가 숨기거나 고치지 않는다.
현재 계약과 기존 검사의 일치 여부를 별도로 검토해야 한다.

새 게임 생성, 여러 파일 변경, 테스트 계약 변경, 실기 배포는 후속 연결 단계다.
이번 버전의 검증은 모의 모델/검사기로 실제 기존 수정 엔진 연결, 실패 복원, 외부 변경 보호,
경로/브랜치 차단, 질문 재개를 확인한다. 실제 Mac Ollama·Docker·기기 플레이는 별도로 확인해야 한다.
