- 외부 유료 API는 사용하지 않는다.

- 같은 My PRJ 폴더를 사용하며 새 worktree는 만들지 않는다.

- 기존 untracked 5개·stash 1개·작업 목록을 보존한다.
- commit·push·merge는 승인 범위 안에서 수행한다.
- main 통합·완료 Child 삭제는 하지 않는다.

## 현재 기능
- text: 응답 저장. python: 코드 저장·문법 검사.
- edit: 기존 파일 수정. create: 없는 Python 파일 하나 생성.
- 문법·고정 Docker 테스트 검사와 최대 3회 재수정을 지원한다.
- 실행 잠금·외부 변경 검사·고정 테스트 보호를 적용한다.
- Docker는 네트워크 차단·읽기 전용 마운트·자원 제한을 사용한다.
- 질문·답변 누적 저장과 --answer 작업ID를 통한 재개를 지원한다.
- 질문·중단·파일 작업 실패 시 목록을 멈추고 성공 시 후속 작업을 진행한다.
- edit는 대상·테스트가 Git 추적 상태이고 기존 변경이 없어야 한다.
- create는 대상 부재와 고정 테스트의 Git 추적·변경 없는 상태를 요구한다.
- create의 질문·최종 실패·처리 가능한 오류에서는 이번 생성 파일만 정리한다.
- 외부 변경이 있으면 파일을 보존하고 중단한다. 후보·로그는 outputs에 남긴다.

## 게임 연결
- 도구 개발과 플랫폼 → 게임 Epic → 작업 Child를 분리한다.
- sandbox 또는 edit_directory로 지정한 게임 폴더 바로 아래만 취급한다.
- 경로 이탈·심볼릭 링크를 차단한다. 현재 Epic에는 게임 폴더를 지정하지 않는다.
- 게임 실행은 도구 commit의 로컬 복사본과 게임 Child 설정을 사용한다.
- ai/game-runtime/은 Git에서 제외하며 게임 소스는 게임 브랜치에 관리한다.
- 기존 게임 실행 복사본은 aea64a7 기준이다. create 사용 전 새 도구 기준으로 갱신해야 한다.

## 제한
- 자동 성공 판정은 지정 테스트 범위이며 Git diff 검사는 별도다.
- 질문은 검증 시 유도했다. 질문 품질·자발적 중요 결정 식별은 미검증이다.
- 실제 게임 폴더의 create·CLI 대화형 답변·장시간 무인 실행은 미검증이다.
- 작업 자동 분할·의존성 관리·강제 종료 복구·Git 자동화는 미구현이다.
- failed 작업은 자동 재실행하지 않으며 다음 실행 전체를 차단하지도 않는다.
- 수정·생성 요청은 누적 답변 포함 4000자로 제한한다.
- 동시 외부 쓰기의 완전한 원자성·게임 전체 제작·화면·실기는 보장하지 않는다.
