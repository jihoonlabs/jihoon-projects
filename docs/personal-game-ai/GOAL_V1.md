# 레트로 게임 경량화·개발 자동화 도구 — 목표 v1

갱신일: 2026-10-08

## 목적과 범위
사용자가 타겟 게임과 타겟 기기를 지정하면 핵심 재미를 분석하고, 기기 제약에 맞는 작은 게임으로 재기획하여 설계·고정 테스트·코드·필요한 데이터를 만드는 도구를 개발한다.

현재 우선 대상은 일반 Thumby다. 최소 확장 목표는 Thumby Color까지이며, 다른 기기는 이후 범위다. 일반 Thumby용 코드나 API가 Color에서도 그대로 동작한다고 가정하지 않는다. 이 문서는 제품 방향을 설명한다. 기존 작업 규칙과 작업 MD·MANUAL 체계는 유지한다.

## 사용자 경험
예: “Thumby에서 구동되는 쿠니오군 시대극 같은 게임을 만들고 싶다.”
사용자는 원하는 게임·기기와 중요한 디자인·시나리오 선택을 정한다. 도구는 조사, 축소안, 명세, 구현, 검증, 재개 기록을 맡는다. 원작은 핵심 재미와 장르를 분석하는 참고 대상으로만 사용한다. 원본을 그대로 복사하는 작업은 절대 금지한다.

## 제작 흐름
1. **입력:** 타겟 게임, 타겟 기기, 원하는 플레이 경험을 받는다. 빠진 필수 정보만 질문한다.
2. **게임 조사:** 핵심 규칙·조작·진행·연출을 조사하고 출처와 불확실한 내용을 구분한다. 전체 원작 데이터 수집은 작은 구현에 필요한 범위로 제한한다.
3. **기기 조사:** 해상도·색상·입력·런타임·메모리·저장 공간·렌더링·오디오 제약을 공식 자료와 실제 환경에서 확인한다. 출처·확인일·실측 여부를 기록한다.
4. **구현 한계 분석:** 요소별로 구현 예상 가능, 축소 필요, 추가 측정 필요를 구분한다. 조사만으로 성능이나 메모리 적합성을 보장하지 않는다.
5. **선택지 제시:** 디자인·시나리오 범위·핵심 규칙·연출에서 결과에 영향을 주는 선택만 묻는다. 추천안과 축소 시 잃는 요소를 함께 설명한다.
6. **명세 승인:** 선택 결과를 개발 명세로 정리하고 승인을 받는다. 명세에는 기기, 최소 플레이 범위, 규칙, 조작, 자원 예산, 파일 계약, 완료 조건과 검증 방법을 포함한다.
7. **자동 개발:** 승인된 명세에서 설계·고정 테스트·규칙 코드·기기 어댑터·필요한 데이터를 생성하고 검사한다. 구현상의 작은 판단과 명백한 오류 수정은 계속 진행한다. 명세를 바꾸는 핵심 결정은 다시 확인한다.
8. **테스트와 개선:** 규칙 테스트, 어댑터 검사, 에뮬레이터 또는 실기 플레이 결과를 구분해 기록한다. 피드백에 해당하는 부분을 수정하고 관련 검사를 재실행한다.

기존 승인과 검증 기록을 재사용할 때는 현재 파일·문맥과의 일치를 확인한다. 이전 승인을 새 산출물의 승인으로 꾸미지 않는다.

## 일반 Thumby와 Color의 경계
게임 규칙과 기기 입출력·화면·오디오 처리를 분리한다. 기기별 프로필과 어댑터로 차이를 표현하되, 공유할 수 있는 규칙은 보존한다. 프로필은 지원 API·자원 예산·검증 환경을 명시해야 한다. Color 지원은 해당 기기의 구현과 검증을 완료한 뒤 선언한다.

## 정보 부족·중단·재개
조사할 수 없는 내용을 추측해서 확정하지 않는다. 먼저 알려진 범위로 진행하고, 꼭 필요한 정보만 사용자에게 요청한다. 모델·Docker·실기가 없으면 독립적으로 검증 가능한 작업을 진행하고 막힌 연결 단계는 미검증으로 남긴다. 작업 문서에는 브랜치·기준 SHA·결과·다음 실행 방법을 남겨 다른 환경에서 이어갈 수 있게 한다.

## 현재 구현과 목표의 차이
자연어 입력과 기존 제작 워크플로 연결은 별도 Child 브랜치에 있다. 게임 조사·기기 조사·경량화 선택지·Color 프로필은 이 문서만으로 구현된 것이 아니다. 일반 Thumby 게임의 rules.py 성공은 집 실행에서 보고된 결과이며, 어댑터 완료와 실기 플레이는 아직 확인되지 않았다.

진행 순서와 상태는 [썸비 Epic](../thumby/EPIC.md)에서 관리한다.

## 원본 복사 금지
원본 코드·캐릭터·기체·명칭·그래픽·음악·대사·시나리오·맵·스탯 데이터의 복제·추출·변환을 통한 재현은 하지 않는다. 원작 도트를 축소하거나 원작 음악을 변환하는 것도 허용하지 않는다. 독자적인 캐릭터·세계관·시나리오·그래픽·음악·게임 데이터를 설계한다. 외부 소재가 필요하면 원작과 무관한 소재의 출처와 사용 조건을 확인한다. 선택지에도 원본 복제를 제안하지 않는다.
