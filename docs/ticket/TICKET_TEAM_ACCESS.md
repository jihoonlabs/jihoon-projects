# Ticket Team Access

## 目的
Ticket の担当者機能を、アプリ管理者が管理するチームと権限の境界内で利用できるようにする。

## 確定した要件
- アプリ管理者がチームを管理し、ユーザーを各チームへ追加する。
- チームメンバーごとに `read` または `write` 権限を持つ。
- `read` は Ticket の閲覧とコメント投稿を許可する。
- `write` は `read` に加えて Ticket の作成・編集・削除、担当者変更、ステータス変更を許可する。
- コメントの編集は権限種別にかかわらず投稿者本人だけが行える。
- コメントの削除は投稿者本人またはアプリ管理者が行える。アプリ管理者でも他ユーザーのコメント本文は編集しない。
- 退職・利用停止ユーザーの業務記録は自動削除せず保持し、必要なコメントだけをアプリ管理者が削除できるようにする。
- Ticket の担当者は、その Ticket が属するチームのメンバーから選択する。
- Ticket の担当者は1名とし、未割り当ても許可する。

## 現在の実装
- Ticket は `assignee_id` で User と関連している。
- Ticket API は現在、任意の既存 User を担当者に指定できる。
- Ticket API は `auth:sanctum` と `active.user` のみで保護され、チーム単位のアクセス制御は未実装。
- コメントの編集・削除は既に投稿者本人に限定されている。

## この Child の範囲
1. Team と Team Member のデータモデルおよび権限境界を追加する。
2. Ticket を Team に所属させる。
3. Ticket の閲覧・変更を Team Member の権限で制御する。
4. 担当者を同一 Team のメンバーに限定する。
5. 必要な Laravel / React の契約とテストを追加する。
