# Ticketの最新詳細と編集競合防止

カードの古い情報を編集基準にせず、詳細を開くたびに最新Ticketを取得します。別のユーザーが先に変更した場合は保存を拒否し、古い編集による上書きを防ぎます。

取得中は古い詳細や編集ボタンを表示しません。取得失敗、削除されたTicket、アクセス権限の喪失は別の案内を表示し、再試行できます。画面を閉じたり別のTicketへ切り替えたりした後の遅延応答は破棄します。

編集では取得したTicketのversionを保持し、保存時の条件付き更新でサーバーが比較します。競合すると入力内容を保持して保存を無効にします。「最新情報を再取得」は最新内容を比較用に表示し、入力を置き換えません。「最新情報で編集し直す（入力を置き換える）」を選んだ場合だけ、入力と保存基準を更新します。自動保存・自動上書き・自動再試行はありません。

保存結果のフィールドとversionは同じスナップショットで返し、画面にも一緒に反映します。独立レビューで見つかった、保存応答直前の別変更によって新versionと古い入力が組み合わされる境界を修正しました。Projectメタデータの後続取得失敗も、成功した保存の失敗として扱いません。

新しいversion migrationを適用してからAPI/frontendを起動してください。従来のPATCH・手動ステータス変更・DnDの契約は維持し、これらの書き込みもversionを進めます。旧クライアントの無条件PATCH自身には競合検出を強制しません。

今回のChildでReact 169件、Laravel 144件（703 assertions）、TypeScript、ESLint、変更ファイルのPrettier、Pint、production buildが成功しました。独立test reviewは修正後に通過し、検討者が関連React 51件を直接実行しました。transaction終了イベントと応答直列化の間に同じDB接続で後続変更を注入する境界も検証しています。

既存.env/DBを変えず、専用の一時SQLite・セッション・キャッシュでfrontend→Laravel→DBを接続しました。API応答mockなしで最新取得・2ブラウザーの200/409・入力保持/再取得・500/403/404・画面切替の6シナリオと、担当者再編集・実ポインタードラッグ・保存/reload・権限・失敗復元の既存回帰9シナリオが成功しました。応答逆転と閉じた画面への遅延保存/再取得はReactのdeferredテストでも確認しています。

初回buildは通信制限、追加ブラウザーの初回起動は一時ツール不足で失敗しました。ツール復旧とハーネス修正後の最終検証は成功し、環境原因の未実行項目・未解決の実行後失敗はありません。証跡と再実行スクリプトは `/private/tmp/ticket-detail-concurrency-check-20261011`、所有・契約・統合前提は [WORK](TICKET_DETAIL_CONCURRENCY_WORK.md) にあります。

Childは統合準備済みです。Epic採用・隔離統合・pushは未実施で、Ticket V1全体を完了とは扱いません。MySQLの別接続同時実行・isolation・row lockは未検証です。SQLiteと決定的境界テストの結果で検証済みとは扱いません。
