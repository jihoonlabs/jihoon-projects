## 1. 프로젝트 목표

Next.js App Router와 Laravel로 실제 서비스에 재사용할 수 있는 인증 기반을 만든다.

- Laravel Sanctum SPA 세션 인증
- 이메일·비밀번호 로그인
- Google·LINE 소셜 로그인
- 이메일 인증과 비밀번호 재설정
- 계정 상태에 따른 접근 제어
- 인증 정책을 Feature Test로 검증
- 공개 GitHub 포트폴리오 수준으로 정리

## 2. 주요 인증 정책

### 로그인 방식

- 이메일·Google·LINE 계정을 자동으로 연결하지 않는다.
- 소셜 계정은 `provider`와 `provider_user_id`로 식별한다.
- provider 이메일은 참고 정보인 `provider_email`에 저장한다.
- 소셜 사용자의 `email`과 `password`는 `null`을 허용한다.
- 사용자는 가입할 때 선택한 인증 방법으로 로그인한다.

### 이메일 계정

- 회원가입 후 이메일 인증 전에는 로그인할 수 없다.
- 비밀번호는 8자 이상이며 영문과 숫자를 포함한다.
- 인증메일 재전송과 로그인·회원가입 요청에 Rate Limit을 적용한다.
- 계정 존재 여부가 외부 응답으로 드러나지 않게 한다.

### 계정 상태

- 신규 사용자의 기본 상태는 `active`다.
- `suspended` 사용자의 일반·소셜 로그인을 차단한다.
- 로그인 후 계정이 정지되면 세션을 무효화한다.

### 비밀번호 재설정

- 인증 완료·활성·비밀번호 보유 계정만 재설정할 수 있다.
- 미등록·미인증·정지·소셜 계정에는 알림을 발송하지 않는다.
- 외부에는 계정 상태와 관계없이 같은 응답을 반환한다.
- 잘못된·만료된·사용 완료 토큰은 거부한다.
- 회원가입과 동일한 비밀번호 정책을 적용한다.
- 재설정 후 해당 사용자의 기존 세션을 무효화한다.
- 재설정 메일 요청과 비밀번호 변경에 Rate Limit을 적용한다.

## 3. 완료된 기능

### Laravel

- 회원가입·로그인·로그아웃·세션 복원
- 이메일 인증과 인증메일 재전송
- Google·LINE Socialite 로그인
- active·suspended 계정 접근 제어
- 비밀번호 재설정 메일 요청과 토큰 검증
- 새 비밀번호 저장과 기존 세션 무효화
- 인증 정책 Feature Test

### Next.js

- 로그인·회원가입 화면
- 이메일 인증과 소셜 로그인 결과 안내
- 인증메일 재전송
- 비밀번호 찾기 화면
- 새 비밀번호 입력 화면
- 잘못된 재설정 링크 안내
- 입력 검증과 성공·실패·Rate Limit 메시지 처리
