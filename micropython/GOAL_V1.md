[GOAL_V1] Retro Game Downscaling & Automated Development Tool Vision
1. 프로젝트 목적 (Project Goal)
본 프로젝트의 최종 목표는 사용자가 [타겟 게임]과 [타겟 기기]를 지정했을 때, AI가 해당 기기의 물리적/기술적 스펙 한계를 분석하여 게임을 마이너 버전(경량화 프로토타입)으로 재기획하고, 개발 뼈대와 데이터를 자동으로 구축해 주는 '레트로 게임 다운스케일링 & 개발 자동화 툴'을 완성하는 것이다.

2. 기본 워크플로우 (System Workflow)
AI 시스템은 독단적으로 작업을 진행하지 않으며, 반드시 아래 8단계 순차 프로세스를 준수하여 실행된다.

[1. 입력] -> [2. 게임 조사] -> [3. 기기 스펙 조사] -> [4. 구현 한계 분석]
|
[8. 피드백/테스트] <- [7. 코드 생성] <- [6. 유저 승인] <- [5. 유저 선택지 제시]

단계별 상세 동작 (Step-by-Step Execution)
타겟 지정 (Target Input):

유저로부터 [타겟 게임]과 [타겟 기기] 정보를 수신한다. (예: GBA 기종 / 슈퍼로봇대전 D)

타겟 게임 정보 취득 (Game Data Retrieval):

원작 게임의 핵심 시스템(그리드 턴제, 정신기, HP/EN 등), 주요 기체/캐릭터 스탯, 시나리오 흐름, 연출 특징 및 BGM 정보를 수집/파싱한다.

타겟 기기 스펙 취득 (Hardware Specs Retrieval):

타겟 기기의 물리적/기술적 제약 조건(해상도, 발색 수, 메모리 용량 제한, 스프라이트 렌더링 규격 등)을 조사한다.

구현 한계 분석 (Feasibility & Downscaling Check):

취득한 기기 스펙을 기준으로, 원작 게임 요소 중 [100% 구현 가능 항목]과 [스펙 한계로 인해 경량화/다운스케일링이 필요한 항목]을 분류하고 한계선을 측정한다.

유저 선택지 제시 (Decision-Point Questionnaire):

AI가 자체적으로 판단하기 어렵거나 유저의 의도가 개입되어야 하는 영역을 추려내어 유저에게 질문을 던진다.

질문 구성 범위:

캐릭터/기체 디자인 방향 (원작 복제 / 픽셀 도트 변환 / 무료 어셋 활용 등)

축소할 시나리오/스테이지 개수 및 구성

기본 디자인 스펙 및 전투 연출 방식 (간이 연출 / 2D 오버레이 / 텍스트 등)

기타 기기가 판단하지 못하는 핵심 기획 요소 전체

유저 승인 (User Approval):

유저가 선택한 답변을 종합하여 [개발 방향 명세서]를 최종 출력하고, 유저로부터 최종 승인(OK)을 획득한다.

자동 개발 (Automated Code & Asset Building):

승인된 명세서와 미리 정의된 에이전트 개발 규칙(AGENT.md)에 따라 데이터 파일(JSON) 및 엔진 소스코드를 자동 생성한다.

유저 테스트 및 핀포인트 피드백 (User Test & Iteration):

유저가 빌드된 마이너 버전을 직접 테스트하고, 수정이 필요한 특정 모듈/기능만 핀포인트로 전달받아 개선 작업을 수행한다.

3. AI 작동 철칙 (Core Rules for AI)
의사결정 권한 제한:

기획, 연출, 디자인의 핵심 결정권은 AI에게 없으며, 반드시 단계 5의 질문 과정을 통해 유저에게 선택권을 부여해야 한다.

하드웨어 제약 최우선 준수:

모든 코드와 어셋 제안은 타겟 기기의 해상도 및 메모리 스펙 범주를 절대로 초과해서는 안 된다.

지식 부재 시 예외 처리:

특정 게임이나 기기의 정보가 부족하여 파싱할 수 없을 경우, 추측해서 소설(환각)을 쓰지 말고 유저에게 기본 스펙 입력을 요청해야 한다.
