# LanternRun — 등불길 배달꾼

TinyCircuits **Thumby 흑백 모델(72×40)**용 오리지널 MicroPython 난투 액션입니다.
밤길의 배달꾼이 길을 막는 무리를 물리치고 세 구역을 지나 소포를 배달합니다.
벨트스크롤 액션의 거리 조절, 깊이 이동, 연타, 넉백을 작은 화면에 맞게 축소했습니다.
상용 게임의 캐릭터·이름·그래픽·맵·대사는 사용하지 않았습니다.

## 설치와 실행

1. [Thumby Code Editor](https://code.thumby.us/)에서 흑백 Thumby를 연결합니다.
2. 기기에 `/Games/LanternRun/` 폴더를 만들고 다음 두 파일을 업로드합니다.
   - `/Games/LanternRun/LanternRun.py`
   - `/Games/LanternRun/lantern_core.py`
3. 런처에서 LanternRun을 선택합니다. 폴더명과 진입 파일명은 위 대소문자를 유지합니다.
4. 타이틀에서 A로 시작합니다. README와 테스트 파일은 기기에 넣을 필요가 없습니다.

런타임 의존성은 기기 기본 `thumby`, MicroPython 내장 `gc`·`sys`, 동봉된
`lantern_core`뿐입니다. 기본 펌웨어의 `/lib/font5x7.bin`을 사용합니다.
별도 라이브러리, 이미지, 음악 파일, 인터넷 연결은 게임 실행에 필요하지 않습니다.

## 조작 방법

| 상황 | 입력 | 동작 |
| --- | --- | --- |
| 전투 | ← / → | 좌우 이동 및 바라보는 방향 변경 |
| 전투 | ↑ / ↓ | 길의 위아래로 이동; 점프가 아닌 깊이 이동 |
| 전투 | A | 공격. 누른 채로 자동 연타하지 않으므로 반복해서 누르기 |
| 전투 | A를 짧은 간격으로 반복 | 3연타; 세 번째는 피해 2, 긴 사거리와 큰 넉백 |
| 전투 | 방향키 + B | 해당 방향으로 짧은 무적 회피; 방향 미입력 시 전방 회피 |
| 전투 / 일시정지 | A+B 약 0.6초 유지 | 일시정지 / 재개; 다시 쓰려면 버튼을 먼저 놓기 |
| 일시정지 | ↓ | 타이틀로 돌아가기; 진행 상황은 버림 |
| 타이틀 | A / B | 시작 / 기기 런처로 종료 |
| 승리·패배 | A / B | 처음부터 재도전 / 타이틀 |

화면 위에는 체력, 현재 구역, 남은 적 수(`E`)가 표시됩니다. 체력 아래의 얇은
막대가 가득 차면 회피를 다시 쓸 수 있습니다. 적 머리 옆 `!`는 공격 예고입니다.
예고 후에는 적이 방향을 바꾸지 않으므로 깊이 이동이나 회피로 피할 수 있습니다.
공격은 바라보는 방향과 발 위치의 깊이가 맞아야 적중합니다.

모든 적을 쓰러뜨리면 `GO>`가 나옵니다. 오른쪽 끝으로 이동하면 다음 구역으로
진행하며 체력이 2 회복됩니다. 세 번째 구역에서도 오른쪽 끝까지 가면 승리합니다.
총 8명(2명 → 3명 → 3명)이며 마지막에는 체력과 공격력이 높은 적이 포함됩니다.

## 파일 구조

- `LanternRun.py`: 기기 진입점, 버튼, 72×40 렌더링, 메뉴·일시정지, 효과음.
- `lantern_core.py`: 기기와 독립적인 이동·전투·적 AI·진행 규칙.
- `test_lantern.py`: PC 전용 표준 라이브러리 테스트와 Thumby API 대역.
- `README.md`: 설치, 조작, 범위와 검증 기록.

## 구현된 기능

- 112픽셀 폭의 구역 3개와 가로 카메라 스크롤, 위아래 깊이 이동.
- 화면 위쪽 HUD와 분리한 플레이 영역, 발 위치 순서대로 캐릭터 그리기.
- 방향·깊이별 공격 판정, 3연타와 짧은 입력 버퍼, 넉백·경직·타격 정지.
- 예고 후 공격하는 추적 AI, 일반 적과 느리지만 강한 적, 간단한 적 간격 조절.
- 회피 재사용 대기, 피격 후 무적과 점멸로 연속 피격 완화.
- 체력 회복을 포함한 구역 진행, 승리·패배·재시작·일시정지·종료.
- 직접 그린 기하학적 캐릭터와 등불길, 비차단 단음 효과음.

성능 목표는 30 FPS입니다. 정수 연산, 플레이어 1명과 재사용하는 적 3명,
고정된 네 캐릭터의 깊이 정렬을 사용합니다. 타일맵, 물리 엔진, 대형 비트맵,
프레임별 객체 생성이나 파일 읽기는 필요하지 않습니다. HUD 문자열 등 작은 임시
객체는 생성됩니다. `gc.collect()`는 시작·재시작·구역 전환에만 호출합니다.
프레임 기반 게임이므로 실제 FPS가 목표보다 낮으면 게임도 느려집니다.

## 실행한 검증

PC에서 프로젝트 루트 기준:

```sh
python3 -B -m unittest discover -s micropython/LanternRun -v
git diff --check
```

14개 테스트 통과:

- 화면·구역 경계, 카메라와 고정된 적 풀.
- 공격 방향·깊이·1회 타격, 연타·입력 버퍼·연타 만료.
- 적 공격 예고 회피, 피해·무적·패배, 회피 재사용 대기.
- 구역 이동·회복·승리·재시작.
- **체력이나 적 상태를 조작하지 않고 입력만 사용하는 3구역 완주**.
- 고정 시드의 15,000프레임 무작위 입력에서 상태·좌표 불변식 확인.
- API 대역을 통한 모듈 import, 메뉴·일시정지·재개·결과 화면·재시작 실행.
- 세 구역의 렌더 함수 호출과 전투 자세, 텍스트 화면 범위, 런타임 import 확인.

위 검증은 CPython에서 수행한 논리·API 호출 검사입니다. API 대역은 픽셀 출력이나
Thumby 펌웨어를 에뮬레이션하지 않습니다. MicroPython 컴파일러와 실제 기기는
이 환경에 없으므로 펌웨어 실행·실기 성능·메모리 사용량은 검증하지 않았습니다.

## 실제 Thumby에서 확인해야 할 사항

- 런처에서 진입 파일 실행, 동봉 모듈 import, 기본 5×7 폰트 로딩.
- OLED에서 캐릭터·공격 예고·깊이·체력·회피 막대의 식별성.
- 가장자리에서 화면 밖 선·사각형의 클리핑, 적이 겹칠 때의 가독성.
- 적 3명과 효과음이 동시에 동작할 때 30 FPS 유지 여부와 장시간 메모리 안정성.
- A 연타와 B 회피 타이밍, A+B 일시정지 조합의 실제 버튼 조작성.
- 효과음 크기와 펌웨어의 음소거 설정 반영.
- 실제 조작으로 3구역 완주, 체력 0 패배, 반복 재시작, 타이틀·런처 복귀.
- 최소 10분 반복 플레이 후 난이도와 피로도 평가. 자동 완주는 재미·균형의 증명이 아닙니다.

## 알려진 한계 / 아직 구현하지 않은 기능

- 실기 미검증 MVP입니다. 성능과 조작감은 하드웨어 확인 후 조정해야 합니다.
- 점프·잡기·던지기·무기·아이템·성장·상점·저장·멀티플레이는 없습니다.
- 구역은 고정 배치이며 이전 구역으로 돌아갈 수 없습니다.
- 마지막 강한 적은 별도 보스 패턴이 없습니다. 배경도 세 구역에서 같은 표현을 씁니다.
- 간단한 간격 조절만 하므로 적이나 플레이어가 겹칠 수 있습니다.
- 공격 도중에는 이동·방향 전환이 제한되며 회피로 취소할 수 있습니다.
- 피격 경직이나 타격 정지 중의 B 입력은 예약되지 않아 다시 눌러야 할 수 있습니다.
- 회피 중 재입력 예약과 재개 카운트다운은 없습니다.
- 화면 글자는 기본 폰트로 읽을 수 있는 영문만 사용합니다.
