# 레트로 게임 및 Ollama 제작 도구 장기 로드맵

> 상태: 장기 비전/계획. 개별 게임 착수 승인이나 일정 확정이 아니다.
> 추천 게임 목록: [RECOMMENDED_GAMES.md](./RECOMMENDED_GAMES.md)

## 최종 목표
레트로 하드웨어별로 여러 장르의 완성도 높은 게임을 만들고, 그 제작 경험을 Ollama 기반 로컬 AI 게임 제작 도구로 축적한다. 이후 다음 하드웨어로 옮겨 같은 장르를 더 높은 수준으로 재구현하고 도구를 확장한다.

**반복 사이클:** 기기 선정 → 장르별 게임 구현·실기 검증 → Ollama 제작 도구에 장르별 템플릿/에셋 파이프라인/빌드·테스트 통합 → 다음 기기로 확장.

## 플랫폼 순서
1. **Original Thumby:** 72×40 흑백 제약에서 장르별 핵심 게임성과 제작 도구의 최소 기능을 검증.
2. **Game Boy / Game Boy Color:** 8비트 타일/스프라이트·메모리 제약에 맞춰 엔진과 도구를 확장.
3. **Thumby Color:** 오리지널 Thumby 및 GB/GBC에서 축적한 시스템을 고성능 MCU·컬러 화면에 맞춰 확장하고 그래픽·UI·효과를 고도화.
4. **Game Boy Advance 및 기타 2D 플랫폼:** Thumby에서 검증한 게임 규칙과 설계 자료를 재사용하되, 해당 기기의 메모리·그래픽·사운드·카트리지 제약에 맞춰 재구현. 최초 대상 모델(DMG/GBC/GBA)은 착수 전 별도 결정.
5. **후속 레트로 기기:** 기기별 가능성과 개발 환경 검증 후 순차 확대. 플랫폼 목록과 순서는 이후 결정.

## 우선 개발 장르와 대표 목표
- SRPG: 슈퍼로봇대전
- 전술·육성: 건담 제네레이션
- 메트로배니아: 악마성 효월의 원무곡
- 액션 RPG/벨트스크롤: 쿠니오군 시대극
- 벨트스크롤 액션: 베어너클
- 대전 격투: KOF
- 리듬: 비트매니아
- 추가 추천(선택 사항): 풍래의 시렌형 로그라이크, 메달롯형 파츠 RPG, 프론트 미션형 전술전, 기타 추천 목록

## 각 플랫폼의 완료 기준
- 장르별 대표 게임이 실제 기기에서 플레이 가능하고 핵심 루프·조작·저장·성능을 검증함.
- Ollama 도구에서 해당 장르의 프로젝트 생성, 게임 규칙/맵/데이터/에셋 편집 또는 생성, 빌드·실행·테스트를 재현 가능하게 함.
- 성능 예산, 플랫폼 제약, 공통 코어와 플랫폼 전용 코드의 경계를 문서화함.
- 모든 장르가 같은 날 완성되어야 다음 단계로 넘어가는 것은 아님. 장르별 완성/도구화/이식 상태를 추적하며 진행.

## 아키텍처 원칙
- **게임 코어:** 규칙, 데이터 모델, 시나리오·맵 포맷, 결정적 테스트를 가능한 범위에서 공유.
- **플랫폼 어댑터:** 렌더링, 입력, 오디오, 저장, 빌드/패키징은 기기별 구현.
- **Ollama 도구:** 장르별 생성·수정 워크플로, 템플릿, 검증기, 에뮬레이터/실기 테스트를 누적.
- 이식은 무조건 동일 소스 재사용이 아니라 **동일한 게임성의 하드웨어 맞춤 재구현**을 기본으로 함.
- 화면 해상도보다 게임의 깊이를 우선하되, 가독성·안정적인 프레임·메모리 안전성·하드웨어 한계 내 그래픽 품질을 동시에 추구.

## 현재 작업과의 관계
- 기존 SRPG 개발은 계속 독립적으로 진행하며 이 문서는 범위 확대를 자동 지시하지 않는다.
- 신규 장르 착수와 다음 플랫폼 전환은 별도 우선순위 결정 및 검증 후 진행.
- 기존 코드·문서·브랜치의 작업 규칙을 우선 준수한다.

## 최종 제품 정의: 범용 레트로 게임 AI 스튜디오
- Thumby 전용 도구가 아니라 **게임기 선택 → 장르 선택 → 프로젝트 생성/편집 → 에셋 제작 → 빌드 → 에뮬레이터/실기 테스트 → 배포**를 지원하는 하나의 Ollama 기반 제작 환경을 지향한다.
- 각 단계에서 만든 장르 템플릿, 게임 데이터, 테스트 시나리오, 에셋 생성기와 검증기를 다음 플랫폼으로 누적 확장한다.
- AI는 제작을 보조하지만, 컴파일·성능·게임성의 검증은 결정적 도구와 실기 테스트로 수행한다.

## 단계별 플랫폼 확장 가설
| 단계 | 플랫폼 | 목표 | 주요 위험 |
|---|---|---|---|
| 1 | Original Thumby | 초소형 흑백 기준 게임과 도구 MVP | 화면 가독성, 메모리, 프레임 |
| 2 | Game Boy / Game Boy Color | 8비트 휴대기 백엔드 | 뱅킹, 타일/스프라이트 제한 |
| 3 | Thumby Color | 고성능 MCU·128×128 컬러 확장 | 런타임/API 차이, 그래픽 처리량 |
| 4 | NES / Game Boy Advance | 서로 다른 2D 하드웨어 대응 | PPU 제약, GBA 성능/에셋 |
| 5 | SNES / Mega Drive / PC Engine | 16비트 2D 제작 도구 | VRAM, DMA, 사운드, 전용 툴체인 |
| 6 (연구) | Neo Geo / PlayStation 1 | 대형 2D·초기 3D 파이프라인 | 에셋 규모, 3D, 메모리 |
| 7 (장기 연구) | Nintendo 64 / Dreamcast / PlayStation 2 | 기기별 전문 백엔드 검토 | 3D 최적화, SDK, 디버깅 |

- **현실적인 중장기 제품 목표는 SNES/Mega Drive급 2D까지.** PS1 이상은 별도 기술 검증을 통과한 후 범위를 결정한다.
- 표의 순서는 대략적인 학습·확장 단계이지 출시 순서나 완료 약속이 아니다. Game Boy, GBC, GBA는 서로 다른 제약을 가진 독립 타깃이다.
- 하나의 공통 소스로 모든 기기에서 같은 성능을 보장하지 않는다. 공통 제작 경험과 데이터 모델을 공유하고 플랫폼별 코드를 생성/최적화한다.

## 플랫폼 확장 승인 조건
1. 현 단계에서 최소 두 장르의 대표 게임이 실기/에뮬레이터에서 재현 가능하게 빌드된다.
2. Ollama 도구가 프로젝트 생성, 데이터·에셋 편집, 빌드, 테스트 결과 수집을 자동화한다.
3. 성능 예산과 회귀 테스트를 통과하며 실패 시 재현·수정 경로가 있다.
4. 다음 플랫폼 SDK/툴체인, 라이선스, 에뮬레이터 및 실기 검증 방법을 확인한다.

## 플랫폼 순서 보정 (2026-10-22)
- Original Thumby와 Thumby Color를 같은 성능 단계로 묶지 않는다. Color는 일반적으로 훨씬 높은 MCU 처리 성능과 더 큰 컬러 화면을 제공하므로 GB/GBC 이후 별도 단계로 둔다.
- 단, MCU 클럭만으로 콘솔 간 게임 성능의 절대 서열을 정할 수 없다. GB/GBC의 전용 타일·스프라이트 하드웨어, Color의 런타임·화면 전송 비용 등 차이가 있다.
- 이 순서는 **제작 도구의 학습·지원 확대 순서**이며 게임기 전체 성능 순위는 아니다.
